## 已完成的整改

- 出库分配、释放在事务内同步货主库存汇总；标准出库与 POS 统一为有日期库存优先、空效期最后的 FEFO。
- POS 还款增加持久化幂等键和请求指纹、客户/仓库并发互斥；相同请求返回原结果，同键异内容拒绝。请求须提供幂等键或非空参考号；旧记录无幂等字段时，同参考号再次收款会拦截并要求核对历史。
- 已收到还款的赊销禁止直接作废，防止缺少退款/冲销单据时产生无法解释的余额。当前还款没有逐销售分摊，按客户采取保守拦截；零价赠品可以退回实物库存而不虚构资金退款。
- POS 同时校验操作权限与仓库范围，保留授权同仓跨货主销售和兼容的旧仓库绑定；明确的角色范围与旧绑定冲突时拒绝。无仓库配置继续返回原有 400，未放宽实际销售入口。
- 普通管理员不能通过后台改密入口操作超级管理员；任务行、指派、状态日志、扫描日志统一应用范围，并校验任务、货主、仓库、商品和库位关系。
- 打印使用 120 秒、单文档票据，读取时继续校验对象权限、账号状态和改密撤销。原打印 URL 中的完整 access token 不再接受，客户端与后端需要协调更新。
- XLSX 在解析前限制压缩体积、展开预算和文件数，相关文本导出防止被识别为公式；Session 登录入口补充限流；镜像排除本地环境凭据和本轮测试产物。
- 五端补齐刷新恢复和账号切换竞态处理，防止旧请求覆盖或清除新会话、以新账号自动重放旧请求。临时错误保留会话/草稿；PDA 对结果不确定的还款保留稳定幂等键。
- 发布编排补充定时任务暂停、等待、恢复及失败停止写入，使用模拟命令验证；本轮没有实际部署。测试编排补充数据库身份护栏、串行锁、逐用例清单和失败停止。

## 证据边界与覆盖缺口

- 本轮全部数据库操作使用经验证的 MySQL 8.0.46 `wms_db_test`，主库重建一次后复用；迁移专项使用独立实例。本轮没有生产数据库写入、生产部署、真实支付、提交或推送代码。
- 完整后端功能回归显式使用测试进程的快速 MD5 哈希器，实际配置写入清单。真实浏览器使用默认 PBKDF2。快速哈希不用于证明口令成本、认证吞吐或容量，未使用 SQLite、跳过迁移或 fake。
- 72.38% 是 `allapp` 的语句覆盖率，不是分支覆盖率或全系统用户路径完成率。移库入口 `tasking/views_relocation.py` 为 22.53%，补货入口 `tasking/views_replenishment.py` 为 27.73%，仍需补充接口/界面验收；逐文件数据见 `backend-complete/file-coverage.csv`。
- 本地 Python 3.12.3、Node 22.22.0；容器 Python 3.12.13，CI 使用 Node 20。本轮没有执行远程 CI，也未在候选镜像内部运行整套业务测试。
- Android 构建生成的本地网络配置已归档为 `android-built-network-security-config.xml`，仓库模板已恢复。构建插件耗时、颜色环境变量和 Bandit 既有 nosec 提示保留在日志中。
- 迁移专项是显著测试成本：本轮准备耗时 1,080.73 秒。只读采样中 828 次 ALTER TABLE 累计服务端耗时约 97 秒；商城本地化迁移另含 183 个模型状态字段操作，曾观察到迁移连接空闲 66 秒。这是耗时定位线索，尚无 CPU profile，不能把全部耗时归因于该迁移。没有为加速改写历史迁移。见 `identifier-migration-*.tsv` 与 `identifier-migration-cost-note.json`。

## 失败与复验记录

初始 6 项业务缺陷、测试夹具字段/关系错误、UniApp 定位/路由断言错误、构建与浏览器读取产物冲突均保留原始证据。两次全量运行在发现失败后中止，均未计为通过：

1. POS 无仓库用户状态码由 400 变为 403：定向复现后修正兼容性，相关测试及最终全量通过。
2. 商城旧断言要求空效期库存先分配：按已确认的 FEFO 规则更新为有日期占用 2、空效期新增占用 2，并核对两条拣货任务合计 4；定向 2 项、相关库存 7 项及最终全量通过。

真实浏览器曾出现一次加购 400，未稳定复现；后续真实下单成功，并补显式等待商品加载和加购响应断言，最终复跑通过。保留该失败证据，不将其描述为已确认并修复的服务端缺陷。截图复核另发现取图早于结果页数据渲染，补充订单状态和金额可见断言后复验通过。
