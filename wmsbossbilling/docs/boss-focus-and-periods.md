# Boss 重点关注与周期统计

Android/H5 共用只读业务接口。没有新增系统推送、短信、企业微信或浏览器后台通知。已读摘要不会处置或关闭业务异常。

## 今日业务首页

首页仅展示一个应用标题，仓库／货主共用一行筛选。先显示服务器业务日的实际入库、实际出库、今日新增、POS 销售／退货、应计收入与回款，再显示当前待办。重点关注最多三条标题；离开摘要默认折叠，展开后显式确认；最新重要动态最多五条。完整日期筛选、周期统计、任务分类和排行迁入经营驾驶舱的“周期统计”，原接口继续兼容。

老板端重新打开或切换账号时默认汇总“全部货主”，不恢复旧版保存的单个货主筛选。仓库老板按其仓库范围查看所有货主的业务，无需逐个授权货主。手动选择货主仅在本次会话中保留，并用于自动刷新、页面导航和明细联动；仓库、历史日期及统计粒度仍保留原有偏好。

新增只读接口：

- `GET /api/reports/boss/today/`：仅接收仓库／货主范围作为业务筛选；经营日期固定为服务器今天，返回 `business_today`、`orders`、`financial`、`backlog`。不执行多年统计。
- `GET /api/reports/boss/today/details/`：`metric=inbound|outbound|inbound_submitted|outbound_submitted|inbound_pending|outbound_pending|inbound_unlinked|outbound_unlinked|overdue|pos_sales|pos_returns|accruals|receipts`；`date_from` 与 `date_to` 必须为同一天，链接保留进入时日期；`page_size` 默认 20、最大 100。实际收发先按订单分页，再以 `document_id` 查询当日商品执行记录，关联原单据查看整单进度。

入库只统计已过账收货，出库按实际完成发运；同订单当日多次执行只计一单。POS 独立显示；未知来源不能把任务当成订单。待办按当前状态而非新增日期计算，已结束收货的入库申请不再计入待收货。

**现有金额数据的实际限制：** 普通入出库单据没有可靠的通用币种字段，POS 商品金额也未保存币种。首页不假设人民币、不把整单金额计入部分收发，不将无币种金额混入已知币种总额。当前这类记录显示“金额未完整记录”或“币种未记录”；商品明细以本次实际数量乘准确关联的单据价格显示参考金额，并明确币种缺失。入库默认零单价不视为免费；出库未计价及未确认的默认零价格不视为零货值。财务应计与回款已有币种，继续分别显示金额。这次未新增币种字段或回填历史数据。

今日指标、重点事项及活动各自轻量轮询，后台暂停、恢复立即更新，失败保留最近成功结果；所有查询和明细重新校验权限。查看周期统计才请求重报表，翻页仍只查询当前趋势页。新版页面需先部署两个 today 接口；若接口返回 404，页面明确提示先更新后端，不静默显示零。

本次首页调整没有新增模型或迁移，复用 `wms_db_test`。应用安装身份、HTTP 白名单和部署链路保持原配置。

## 后端先行

新增迁移 `reports.0010_bosscheckstate_bossreadprogress`，只增加查看进度和检查状态；活动仍从原业务表及审计记录读取。应用后端正常发布流程执行真实迁移后，再发布 H5 与 Android 资源。旧客户端继续使用原接口，只有新版客户端取消前端日期上限。

新增 GET 接口（前缀 `/api/reports/boss/`）：

- `attention/`：当前未解决的高风险/严重异常及处理超期异常，独立于统计历史日期；`page`、`page_size` 默认 20，上限 100。
- `digest/`：当前用户及当前授权范围的未确认摘要，返回签名 `token`；只有 `POST digest/?warehouse=...&owner=...`，正文 `{ "token": "..." }` 才推进自己的查看进度。
- `digest/details/`：携带摘要 token、category、action 与游标查询同一时间窗口，token 有效期 24 小时，失效后刷新摘要。确认只到返回的查询截止时间；跨设备确认只能向前推进。
- `periods/`：日期范围不限制天数；`granularity=auto|day|week|month|year`，每页默认 100 个周期，上限 200。首尾周期只计算与查询范围相交部分。
- `periods/summary/`：全区间统计、前一期及去年同期的实际日期和记录数/金额，`preset` 表示快捷日期选择，手选为 `custom`。
- `periods/details/`：按 `metric` 查询对应记录。库存先按商品、单位、货主、仓库分页分组，再点击查询原始流水；“当前库存”不是历史期末余额。
- `sla/details/`：`ratio=on_time|in_full|otif|coverage`，列出分母订单并明确每条是否计入分子，显示实际加工时间。

所有接口、分页及摘要确认均检查 Boss 权限与当前仓库/货主范围。无权更改他人查看进度。切换范围或权限变更后，原摘要 token 不再有效。日期仍须有效、开始不晚于结束、结束不晚于服务器业务今天；数据库有效日期格式不等于跨度上限。

## 页面刷新与后台检查

首页账号菜单 → “刷新与检查设置”。两项默认关闭，开启后选择 1、3、5、10、30 分钟或自定义 1～1440 的整数分钟；首次建议值为 5 分钟。修改后保存生效。

- 页面偏好保存在当前设备、当前账号下；关闭时仅首次进入、切换筛选或手动刷新读取数据，不进行自动重试或恢复前台刷新。开启后前台按所选间隔读取当前页面，隐藏时暂停、恢复后立即刷新；失败等待 2 倍、4 倍间隔，成功恢复原间隔。
- 后台检查为全系统配置，仅有效超级用户可以修改。`GET/PATCH /api/reports/boss/automation-settings/` 提供配置、`can_manage` 和调度状态；PATCH 仅接收 `enabled` 和 `interval_minutes`，写入与审计处于同一事务。个人页面刷新不触发后台业务扫描。
- 全局配置复用 `SystemSetting` 的 `boss.automation_settings` JSON。未配置即关闭；开启时间由服务器记录。`BossCheckState` 的 `BOSS_SCHEDULE_RUN` 记录最近调度开始、结束和失败状态，`BOSS_SCHEDULE_WORKER` 记录进程心跳；原四类检查行仍表示实际成功检查时间。
- 常驻进程每 30 秒读取配置并更新心跳；关闭时仅查询配置和运行状态，不扫描订单、任务或计费表。每轮结束后按所选分钟数安排下一轮，配置变化在下一次轮询生效。关闭不打断已开始的一轮。
- MySQL 命名锁覆盖配置复查、到期判断和整轮执行，多个进程不会重复扫描。重启只执行一次已到期检查；失败也从结束时间按所选间隔重试。每类检查失败仍回滚该类事务，不能误恢复异常。
- 最近一轮日志记录 `duration_seconds`、`failed` 和各类数量；失败带后端异常日志。容器初始限额为 0.5 CPU、512 MiB，可通过 `WMS_BOSS_CHECK_CPUS`、`WMS_BOSS_CHECK_MEMORY_LIMIT` 配置；这些限制不限制 MySQL 本身的查询开销，真实负载需单独验收。
- `attention.automation` 及原 `checks` 的新增字段区分 `disabled`、`waiting`、`running`、`healthy`、`failed`、`worker_unavailable`、`delayed`。心跳中断超过 2 分钟提示未连接；持锁执行期间按运行状态显示。调度超过到期时间加 2 分钟提示延迟。主动关闭不显示失败，空列表明确说明检查结果待更新。

### 开发运行

在确认使用开发配置和开发数据库的后端环境，单独启动：

```sh
python manage.py boss_run_checks
```

默认关闭时该进程不会扫描业务。按配置单次运行或明确强制检查：

```sh
python manage.py check_boss_deadlines
python manage.py check_boss_deadlines --force
```

### 生产切换

先部署包含本次接口及命令的后端镜像，停用旧 timer，再启动常驻服务：

```sh
sudo systemctl disable --now wms-boss-deadlines.timer
docker compose -f compose.production.yml up -d boss-check-worker
docker compose -f compose.production.yml logs --tail=100 boss-check-worker
```

沿用部署环境已有的 `WMS_IMAGE` 和 `WMS_ENV_FILE`。旧 `boss-deadlines` one-shot 命令保留，但默认也检查开关与到期时间，残留 timer 不会绕过关闭设置。新服务保持运行并等待配置，前端上线后由超级用户启用。回退时先关闭全局开关，等待当前轮次结束，再停止 `boss-check-worker`；保留异常和处理历史。尚未提供新接口的后端会让设置页面明确显示加载失败。

本次不增加模型字段或迁移；此前重点关注功能所需的真实迁移仍须已部署。数据库测试复用健康的 `wms_db_test`。

### 业务判断口径

- 入库使用预计到货时间 `eta`，出库使用预计发货时间 `etd`；仅正式提交、未关闭且未取消/驳回的业务，按剩余实际收货/发运数量检查。
- POS 关联出库单不另作待发运订单告警。
- 作业任务使用 `planned_end`；草稿、冻结预订、取消及已完成任务不告警。
- 原异常的 `due_at` 用于处理超期，业务期限和处理期限分别展示。
- 没有期限的任务明细显示“未设期限”，不强行套用等待小时数。负责人由原授权管理端指派，老板端只查看。

业务超时从后台检查发现到页面显示的延迟包含后台检查间隔、执行耗时、页面刷新间隔及网络耗时；页面显示最后更新时间，不宣称秒级送达。多年经营统计不加入自动轮询。阅读缓冲只保留业务内容，检查健康状态在请求成功时独立更新。

## 统计口径

自然周从周一开始。本周、本月、本年截至业务今天；自定义时间段前一期使用相同天数。同比处理闰年；无可用比较日期返回不可用。历史日志完整性不能证明时不提供伪精确增长率。

单据正式提交、库存过账、任务完成、发运分别按各自发生时间统计。收货单数与发运任务数明确区分，不能混称销售单数。库存流水包含 POS 的真实扣减，活动笔数对 POS 关联流水去重；库存移位同仓净变化为零。

应计金额采用账本中可计入财务的有符号金额，按原币不含税统计；开票金额为账单总额；回款冲销按负向计入净额。POS 只汇总获授权商品行金额，不分摊整单收付款；源记录未保存币种时标记 `UNKNOWN`，不猜测人民币。

多年度查询在数据库聚合并分页；自动粒度为 31 天以内按日、180 天以内按周、约 3 年以内按月、更长按年。手动选择按日也不会被强制改成年或缩短查询日期。

## 验收环境

自动化数据库只允许 MySQL `wms_db_test`。新增迁移需要从空库验证真实迁移链，再复用健康测试库；不能对 `wms_db` 做测试写入。浏览器自动化使用受控模拟接口证明交互，MySQL 测试单独证明业务与权限；两者不能替代生产网络和 Android 真机验证。

上线后检查常驻服务实际运行、检查时间持续推进、历史异常与实际业务一致，并确认旧 timer 已停用。再用远程浏览器和原签名 Android 测试包验证前后台恢复、退出登录、断网及多端确认。`build:app` 产物只是 App 资源，不是已签名 APK。
