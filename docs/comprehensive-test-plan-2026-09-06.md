## 业务验收规则

- 已收到还款的赊销不得直接作废，不能清零余额掩盖已收款；先完成明确退款或冲销。
  当前还款按客户记录，缺少逐销售分摊，暂对有未冲销还款的客户赊销作废作保守拦截。
- 在允许出库的库存中，FEFO 按有效日期升序、空效期最后；标准出库与 POS 一致。
- 零价赠品可退回实物库存，不虚构资金退款。
- 同一请求重放不得重复改变库存、资金、订单、任务或账单；同键异内容必须拒绝。
- 角色权限和数据范围同时满足；列表、详情、直接 ID、Admin、导入导出、打印一致。

## 数据库与执行边界

仅允许 MySQL 8 和准确名称 `wms_db_test`。加载 `.env.test.local`，验证 APP_ENV、
Django 主库/测试库配置及 SELECT DATABASE()；连接检查超时五秒。不打印秘密。
测试使用合成数据，禁止自动化写入 `wms_db`，禁止 SQLite、跳过迁移和 fake。

正常使用 `--reuse-db`。迁移变更、确证 schema 损坏、迁移专项或最终发布门禁才
允许重建，报告原因。普通数据库测试串行，业务并发由独立连接在用例内部完成；
禁用会生成其他 schema 名称的 xdist。CI 不同隔离实例仍使用同名 `wms_db_test`。
商品标识迁移使用独立临时容器、合成旧版本数据、真实升级和恢复 HEAD，不能因
独立运行而从强制验收清单遗漏。

现有快速测试 Compose 的耐久参数不适合证明灾备能力。故障和恢复演练必须使用
独立测试实例及生产等效的耐久参数，库名仍为 `wms_db_test`。

### 对账的必要条件

每条闭环在事务内部或保留的合成验收数据上验证：

1. 可用 = 在手 - 预占 - 锁定 - 残次，汇总与明细一致。
2. 流水回放与在手一致；移动两端守恒；预占独立断言。
3. 销售、支付、还款、退款、客户欠款与班次逐笔可解释。
4. 账单头/行/计提/规则/事实可追溯；锁账后无静默改变。

全局或货主对账必须不带 `--warehouse` 再运行一次，因为仓库过滤会跳过货主商品
汇总检查。pytest 清理后的空库零问题不能算业务闭环证据；保留预期非零记录数。
不得自动执行修数命令掩盖差异。

## 性能与灾备目标

- 2 仓、10 货主、1 万商品、10 万库存明细、100 万流水、10 万订单、12 个月账务。
- 固定资源与部署版本，预热 5 分钟；50 并发持续 30 分钟、100 并发峰值 5 分钟。
- 50 并发分配为 25 PDA、10 货主、5 POS、5 商城、5 报表；同仓热点和跨仓分别测。
- 查询 P95 ≤800ms、核心写入 P95 ≤1.5s、非预期错误率 <1%；库存资金错误为零。
- 记录 P50/P95/P99、吞吐、CPU/RSS、连接、锁等待、慢查询和积压；外部支付耗时单列。
- 故障包括 DB 断连、锁超时、提交前后退出、Redis/支付超时、打印断连和调度重启。
- RPO ≤24 小时，RTO ≤60 分钟；核验备份校验和、数据/媒体、迁移及业务闭环。
- 发布和应用回退须演练；不可逆数据库迁移按备份恢复或前向修复处理，不能假设可直接反迁移。
- 发布后至少观察 60 分钟，检查实际支付/计费任务及业务对账，不能只看 SELECT 1。

## 执行入口与结果

统一入口为 `scripts/run_system_tests.py`，各阶段都必须指定独立证据目录：

```bash
.venv/bin/python scripts/run_system_tests.py preflight --artifacts var/system-tests/<sha>/<run>/preflight
.venv/bin/python scripts/run_system_tests.py collect --artifacts var/system-tests/<sha>/<run>/collection
.venv/bin/python scripts/run_system_tests.py targeted --artifacts var/system-tests/<sha>/<run>/targeted
.venv/bin/python scripts/run_system_tests.py backend --artifacts var/system-tests/<sha>/<run>/backend
.venv/bin/python scripts/run_system_tests.py frontend --artifacts var/system-tests/<sha>/<run>/frontend
# 前端构建完成、无其他数据库测试运行后，再串行运行真实 API 浏览器验收：
.venv/bin/python scripts/run_system_tests.py browser --artifacts var/system-tests/<sha>/<run>/browser
# 候选版本稳定后执行；将重建 wms_db_test：
.venv/bin/python scripts/run_system_tests.py release --artifacts var/system-tests/<sha>/<run>/release
```

功能回归可显式增加 `--fast-password-hashers`，仅在已验证的测试进程中使用快速口令哈希，
避免夹具反复建用户占用大部分时间；默认仍使用实际配置。清单记录实际哈希器。
认证配置、口令计算成本和性能容量验收必须使用真实哈希配置，本轮真实 API 浏览器验收保持默认配置。

入口输出命令、退出码、持续时间、日志、JUnit、覆盖率和阶段清单；它不会代替缺失
的真实 API E2E、真机、支付、容量或灾备验收，也不会自动部署生产。

顺序：工具护栏 → 已知问题复现 → 最小整改复验 → 相关模块/并发 → 全量及候选
版本干净迁移门禁 → 外部验收 → 发布演练。普通修改不反复重建或重跑发布门禁。
总收集清单与分组执行清单必须核对，不能仅统计 tests.py 或根据静态数量推定通过。
