# 商品通用品名与品牌型号

商品名称用于通用品名，例如“汽水”。品牌沿用品牌字典，型号单独填写“橙诺橙味”，规格填写“480ml×12瓶”。`brand_model` 和 `display_name` 是计算展示值，不用于定位商品。商品 ID、货主商品编码、SKU、条码和库存关联保持不变。

## 发布顺序

1. 部署代码并执行新增迁移，确认所有服务实例均已更新后再补录和改名。迁移只增加型号和单据快照字段，不自动拆分或改名。
2. 使用 `backfill_product_snapshots` 预检，再用 `backfill_product_snapshots --apply` 分批补录。可用 `--owner 货主编码` 限定范围，`--batch-size 500` 控制每批大小。重复执行不会覆盖已保存的快照。
3. 核对所有待整理商品的关联单据已补齐快照。普通商品编辑、品牌改名和批量映射均拒绝绕过此步骤。
4. 导出映射表，人工填写新名称、品牌编码和型号，预检通过后应用。

以下命令应由有权限的运维人员在明确配置的目标环境执行；自动测试仅使用 MySQL 8 的 `wms_db_test`，不得对 `wms_db` 进行测试重置或迁移。

```bash
python manage.py product_identity_mapping --owner OWNER --export /tmp/identity-mapping.csv
# 人工填写 CSV 的后三列；保留原资料列及商品编码。
python manage.py product_identity_mapping --owner OWNER --input /tmp/identity-mapping.csv --report /tmp/identity-preview.json
python manage.py product_identity_mapping --owner OWNER --input /tmp/identity-mapping.csv --report /tmp/identity-applied.json --apply
```

映射表每次最多 1000 行。报告和导出文件必须使用新路径，避免覆盖已有记录。原名称、品牌、型号或规格与当前资料不符时，整批拒绝写入；同一文件重复商品编码、无效品牌、超长字段也会拒绝。名称整理不产生收货、库存或价格变化。CSV 导出对公式起始字符进行文本转义，回导时解除对应转义。

需要撤回名称整理时，重新导出当前映射表，依据应用报告的 `before` 值填写新值，再执行预检和应用。不要回退或删除单据快照字段。

## 历史与接口

- 出库、销售、POS、入库和退货明细保存商品名称、品牌型号及规格快照。修改数量或价格不刷新快照；更换商品则重新捕获。
- POS、关联退货和入库回执继承来源明细快照；重新下单使用当前商品资料。历史详情、销售明细导出和出库打印读取快照。
- 旧单补录只能保存上线前可取得的资料，不能恢复此前未记录的商品改名历史。已有入库、实物退货文字优先保留。
- 商品接口保留 `name`、`spec` 等既有字段，新增可写 `model` 及只读 `brand_model`、`display_name`。单据接口新增 `brand_model`、`product_display_name`，名称及规格字段改读快照。
- Excel v13 增加型号及只读品牌展示列，仍接受 v8—v12 模板。只读品牌名称/品牌型号列不参与更新；写入品牌仍使用品牌编码。
- 无商品编码、无标准贸易条码的收货导入，只有名称、品牌、型号、规格完整且唯一匹配时才能复用已有商品；信息不全时必须提供商品编码。收货导入不会修改已有档案。
- 通用 Excel 用于外部软件整理商品资料；本次未实现特定税务平台导入格式、税额计算或开票接口。历史订单导出仍保持原业务数量与金额口径。

## 验证重点

使用相同名称和规格、不同品牌型号的两个商品，验证搜索、选品、购物车、收货、库存及导出按商品 ID 分离。再修改名称、品牌及型号，核对旧单和退货的显示保持不变，新单采用新资料。发布验证须执行真实迁移链和相关 MySQL 测试；环境阻塞不能计为通过。
