## 已修复并验证

1. 有包装语义的条码只有在条码、商品和包装均启用、未软删除且处于有效期内时才参与搜索和解析。
2. 库存流水 Console 和老板库存明细接入统一商品标识搜索，并保留货主、仓库和角色范围隔离。
3. 标识维护禁止将停用、过期、未生效或软删除记录设为主码；禁止为失效包装新增箱码/包装码。
4. 标识写入的唯一性竞争统一转换为业务并发错误；主码切换和注册表同步置于事务及行锁保护中。
5. 标识维护 Excel 补充“基础单位换算快照”。
6. `OTHER` 条码按可重复商品识别码处理，不再占用任务标签唯一键。
7. POS 商品列表消除逐商品库存查询；Console 和报表使用子查询，避免历史标识放大分页与聚合。
8. 一件代发“商家编码”只匹配货主商品编码或当前有效外部标识，不再匹配仓库 SKU。
9. CI 显式配置隔离测试库及并行建库权限；显式 `APP_ENV=test` 的管理命令会加载本地隔离测试环境。
10. 系统管理员、POS、货主业务员和系统测试手册已更新并重新生成。

## 未通过或未完成的强制门禁

1. POS MySQL 并发仍有两个稳定失败：
   - `test_same_sku_concurrent_checkout_cannot_oversell` 的失败方收到 MySQL 1213，而不是业务 `ValidationError`。
   - `test_reverse_product_order_checkouts_do_not_deadlock` 仍可能死锁。
   - 局部给 POS 增加仓库锁会与普通任务过账、退货和作废形成相反锁序，因此没有保留该风险修复；需要统一全部库存过账入口的全局锁顺序。
2. Operations ETL 的既有 `on_time` 断言失败；本次统一搜索改动不经过该计算路径。由于干净 HEAD 基线数据库权限不足，尚未完成基线归因。
3. 部分辅助出库旧测试仍与当前权限策略漂移（403/404、审批任务和 fail-closed 范围），不属于商品标识路径，但使全仓门禁无法全绿。
4. 全局 Ruff 当前 223 条、干净 HEAD 254 条；全局 Flake8 当前 2203 条、干净 HEAD 2398 条；全局 isort 当前 200 个失败文件行、干净 HEAD 203 个。改动未增加债务，但 CI 全局静态门禁仍不是绿色。
5. 948 条全仓串行、五分片 `pytest -n auto` 和合并覆盖率未形成全绿结果；因此没有覆盖率 ≥70% 的本轮证明。
6. 迁移成功路径和全量重放已验证，但“预检冲突在 DDL 前原子失败”的 `MigrationExecutor` 用例未在真实迁移模式完成。
7. 缺少 products 0009 之前的脱敏业务备份，未执行一次性数据库恢复、迁移前后行数/冲突/耗时/锁影响演练。
8. 未在真实测试环境完成浏览器、PDA/POS 和扫码枪人工冒烟；本地 Playwright 只能覆盖 PDA 浏览器自动化。
9. 本机没有 Redis 7，未复现 Python 3.12 + MySQL 8.0 + Redis 7 的完整 CI 组合。

## 发布建议

在以下条件全部满足前保持“不可发布”结论：统一库存过账锁顺序并修复 POS 并发；清理或调整历史全局静态门禁；在干净数据库完成全仓串行、五分片和覆盖率；补跑迁移冲突原子性及脱敏备份演练；在测试环境完成真实设备人工冒烟。
