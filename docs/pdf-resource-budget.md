# PDF 资源预算设计与开放风险

状态：`R-PDF-RESOURCE / REVIEW_REQUIRED`。候选代码已实施资源限制，生产容量验证和具名签收仍阻断发布。

2026-10-05 候选控制：Linux 独立子进程渲染，仅允许 `data:` 资源；每个容器同时最多一个渲染，
在查询单据明细和生成 HTML 前取得渲染名额，不排队，忙时返回 503 和 `Retry-After: 5`。
`PDF_MAX_LINES` 暂以已量测的 1000 行为默认上限，查询最多载入上限加一条明细；超限返回 422
及拆单提示，不生成不完整 PDF。业务若需要更大上限，须先量测再配置。
子进程默认虚拟地址空间 1 GiB、CPU 120 秒、
墙钟 150 秒、输入 HTML 4 MiB、PDF 输出 16 MiB。超时会终止并回收子进程；渲染失败不会
向用户返回内部错误或业务正文。子进程不继承数据库和支付环境变量。

配置项为 `PDF_MEMORY_BYTES`、`PDF_CPU_SECONDS`、`PDF_TIMEOUT_SECONDS`、
`PDF_MAX_HTML_BYTES`、`PDF_MAX_OUTPUT_BYTES`，均须为正数。生产 Compose Web 默认 2 GiB、
2 CPU、128 个进程上限，可通过 `WMS_WEB_MEMORY_LIMIT`、`WMS_WEB_CPUS` 调整。
地址空间限额不等于 RSS，容器内存还包含 Web worker 等开销，不能据此直接宣称容量达标。
这些默认预算以既有 1000 行约 495 MiB 峰值量测为起点，须在真实候选环境复测最大合法单据、
并发时普通接口延迟、取消和故障恢复；不改变历史量测的环境或结论。

历史测试进程的 120 秒超时只保护测试执行；本次新增的线上控制需独立验收。

候选运行环境还需重测常见单、最大合法单、较长业务文本及内联资源。必须记录实际 CPU/内存配额、
Web worker 数、同时渲染数、排队时间、超时与失败率、取消后资源回收，以及普通业务接口是否受影响。

预算采用以下决策顺序：

1. 明确合法单据最大行数、业务文本长度和内联资源体积；根据业务现状选择分页/拆单等产品行为。
2. 实测空闲 Web 进程和单次渲染增量，预留操作系统、其他请求及故障恢复空间，再决定渲染并发上限。
3. 若需要可靠中止长时间渲染，在独立进程中执行并落实内存、时间、队列和取消限制；不能用 HTTP 超时替代进程终止。
4. 验证正常单的中文、价格、分页与权限，并验证超限返回、工作进程存活、排队有界及资源回收。

线上继续仅允许 `data:`，不扩大到文件或媒体路径。离线手册工具有独立的文件资源边界。
