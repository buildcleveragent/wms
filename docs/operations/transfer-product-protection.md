# 跨货主转售商品保护与打印单位

所有代货主转售使用永久来源绑定。绑定同时覆盖旧映射（含停用、软删除）和历史转货明细，不因取消订单或停用映射解除。新转货只使用明确绑定，不能靠同名、相同条码推断商品身份。第一货主的原条码仍用于拣货扫描。新档案沿用可用条码；如果接收货主已有相同条码，先核实并建立明确对应，系统不会自动关联或另造冲突档案。

接收商品的名称、规格、品牌型号、基本单位和追踪规则受保护；双方已有包装单位与换算比例也受保护。来源名称等描述更正会在事务中同步，旧单显示快照；新增包装从来源侧同步。接收方经营价格独立维护。更改计量规则须新建来源商品。

## 发布顺序

1. 完成 MySQL 8 测试库的真实迁移与业务验证。生产部署先停止旧进程写入，避免旧代码绕过新保护。
2. 备份业务库，部署后端并执行迁移：products/0016 建表及补齐历史来源，outbound/0014 增加打印单位快照。旧来源冲突会保留为多条绑定，由检查报告列明，不能继续新转货。
3. 执行只读全局检查：`python manage.py audit_transfer_products`。命令不会修改商品、单据或库存。
4. 按报告逐项审核修复。修复完成后开放对应转货业务。历史有多来源、未完成单据、非零库存、成本单位冲突或其他业务单据时，通用修复命令拒绝执行，不能直接改 SQL 绕过。

开发测试必须使用 `.env.test.local` 中的 `wms_db_test`；上面生产步骤为发布操作说明，本次代码实现不会自动迁移或修复业务库。

## 检查与修复

先用 `--target-product <商品ID>` 或 `--binding-id <绑定ID>` 缩小检查范围。报告提供来源/接收资料、字段差异、库存、历史记录数量、阻断原因及审核签名。

如果恢复基本单位，必须明确价格含义后重新生成报告：

- `--price-basis current`：当前主档默认价、进价、最低价以当前基本单位计价，按来源包装比例折算。
- `--price-basis source`：这些价格已经是来源基本单位价格，保持数值。

不根据价格大小猜测单位，也不调整历史成交价、流水或成本。换算不能精确存入当前主档价格精度时拒绝自动修复。

审核具体报告后执行：

```bash
python manage.py audit_transfer_products --binding-id <绑定ID> \
  --price-basis <current或source> --apply \
  --expected-signature <报告中的signature> --actor-id <有效系统管理员ID>
```

执行会加锁并重做检查。资料或影响范围变化导致签名不一致时停止。成功修改记录审计事件 `products.transfer.repair`；整次修改失败则回滚。此命令不处理合并不同业务商品，也不解除来源保护。

## 打印

送货单有包装可选时先显示预览，每行可选择基本单位或订单快照中的包装单位，点击“更新预览”或“确认并打印”。例如 75 斤、3 元/斤、1 袋=50 斤，按袋显示 1.5 袋、150 元/袋、225 元。库存和成交金额不受选择影响。

新单即使按基本单位开单，也记录当时可用包装的单位名和比例。旧单只使用自身保存的包装比例，不用当前商品比例补猜；无可靠比例时仅按基本单位打印。合计按显示单位分别列出；实际出库扫描和库存流水校验继续生效。
