# WMS 角色—入口—权限—数据范围—动作核对表

本表为 V2.1，基线为 2026-09-07 当前工作区（含未提交改动）中的 `UserRoleScope`、规范角色组模板、Profile 能力字段、客户端菜单和服务端动作校验；不代表这些改动已部署。代码与测试定位见 [内容核对记录](CONTENT_REVIEW.md)。

## 规范角色矩阵

| 角色 | 正式权限组 | 入口 | 显式数据范围 | 默认核心权限 | 主要动作 | 明确禁止或非默认能力 |
|---|---|---|---|---|---|---|
| 仓库操作员 | `WMS::仓库操作员` | `wmspda` | 单一仓库 | 仓库作业、无订单收货、任务查看/领取、代办出库、仓库运营报表、移库申请、要货申请 | 有/无订单收货、上架、代办出库、拣货、复核、库存查询；功能启用后申请及执行移库/补货 | 不做货主/仓库管理审核、异常恢复或过账重试；商品 Excel 导入和 POS 需额外权限 |
| 仓库管理员 | `WMS::仓库管理员` | Web 控制台 / Admin，已开放的 PDA 管理页 | 单一仓库 | 仓库管理、入出库确认、任务管理、库存查看、运营报表与导出、移库管理、补货策略/评估/申请审核 | 入出库确认、保留任务发布、驳回、任务审核/过账；启用后审核/直接下发移库及管理异常、监督补货 | 不代替货主审核或操作员扫码；计费、商品导入、POS 和权限管理非默认能力 |
| 仓库老板 | `WMS::仓库老板` | `wmsbossbilling` | 可配置多个仓库 | 老板看板、仓库运营、仓库财务、运营导出 | 查看经营总览、库存库容、收入计费和预警 | 只读，不开单、不审核、不调整库存、不发布或过账任务 |
| 货主管理员 | `WMS::货主管理员` | `wmsownersale` | 单一货主 | 货主管理、货主财务、货主运营报表与导出、入出库查看/修改/货主审核 | 审核并冻结库存、带原因退回、取消、库存/履约/账单核对 | 不做仓库确认和实物作业，不查看其他货主 |
| 货主业务员 | `WMS::货主业务员` | `wmsownersale` | 单一货主 | 货主业务、货主运营报表、入出库查看/新增/修改/提交 | 选择授权仓库、开单、草稿、提交/撤回、退回后编辑重提、一件代发导入 | 不做货主审核、仓库确认或任务过账，不查看其他货主 |
| 系统管理员 | 无 `UserRoleScope` 业务角色；使用超级管理员或审批后的后台权限 | Web 控制台 / Admin | 超级管理员全局；普通后台账号仍按显式范围 | 用户、角色范围、辅助权限、基础资料、配置和审计 | 开通/停用账号、维护角色范围、基础资料与受控配置、审计排查 | 不代替业务岗位；普通后台权限不能绕过角色范围 |

## 关键业务动作与责任分工

| 动作 | 发起角色 | 后续责任角色 | 服务端关键控制 |
|---|---|---|---|
| 标准出库开单与提交 | 货主业务员 | 货主管理员 | 原创建人、货主范围、授权仓库、价格、库存和幂等校验 |
| 货主审核通过 | 货主管理员 | 仓库管理员 | 仅已提交订单；重新校验价格；冻结库存并生成 `RESERVED` 任务 |
| 货主退回修改 | 货主管理员 | 原创建业务员 | 退回原因必填且不超过 200 字；订单回到可编辑草稿 |
| 仓库确认发布 | 仓库管理员 | 仓库操作员 | 必须先货主审核；只允许完整分配且唯一的保留任务发布 |
| 撤回、驳回或取消 | 业务员、货主或仓库管理角色按状态执行 | 仓库管理员核对 | 任务已开始或有执行数量时禁止直接释放；成功后核对冻结库存 |
| 有订单收货与上架 | 仓库操作员 | 仓库管理员监督 | 只能领取并执行当前仓库任务；库位必须属于任务仓库；请求幂等 |
| 无订单收货 / Excel 入库 | 仓库操作员 | 仓库管理员核对 | 明确货主和仓库；模板范围、追溯字段和整批一致性校验 |
| GS1 辅助建档 | 有无订单收货权限且货主在授权范围内的操作员 | 系统管理员维护服务配置和异常商品 | 本地商品优先；选择有效分类/单位及追溯信息；建档并加入清单不会直接增加库存 |
| 移库申请 / 直接下发 | 操作员申请，管理员审批或直接下发 | 操作员领取并执行，管理员核对过账 | 申请/管理、PDA 执行、整容器功能分别启用；单仓来源和目标校验；普通管理员不代替操作员扫码 |
| 要货申请 / 补货 | 操作员申请，管理员审批或维护补货策略 | 操作员领取并执行，管理员核对过账 | 手工、PDA、阈值、出库需求分别启用；来源库存及在途补货校验；本次增量不能超剩余量 |
| 移库异常恢复 / 作废、移动任务过账重试 | 授权仓库管理员 | 原领取操作员核对现场实物 | 在原任务处理，保留扫描与原因；已过账移库不能直接作废 |
| 拣货与标准复核 | 仓库操作员 | 不同操作员复核，仓库管理员监督 | 标准出库拣货人与复核人分离；完成后统一过账 |
| 库存调整 | 取得相应高风险权限的管理人员 | 仓库管理员/系统管理员审计 | 必须有真实原因和依据；不得直接改库存明细或汇总 |
| 账单核对 | 货主管理员、取得财务权限的仓库角色、仓库老板 | 财务/系统管理员排查 | 按角色范围读取；差异追溯业务来源，不直接改总额 |
| POS 收银 / 还款 / 退货 / 交班 | 具有相应独立 POS 权限的收银或管理人员 | 按 POS 专项分工核对 | 不由仓库角色自动授权；仓库内 POS 客户、有效班次、金额与幂等校验；打印失败不能重复结账 |

## 条件能力与配置核对

以下开关在代码中默认均为关闭。规范权限模板已经包含相关职责，但既有账号可能使用经过定制的组权限；实际入口还需通过 Profile 能力、角色范围和服务端校验。

| 能力 | 功能开关 | 普通岗位权限条件 |
|---|---|---|
| 移库申请 | `RELOCATION_REQUEST_ENABLED` | 操作员角色、任务领取权限、`tasking.request_relocation` |
| 移库审批 / 直接下发 | `RELOCATION_REQUEST_ENABLED` | 仓库管理员角色、任务管理确认权限及 `tasking.approve_relocation` / `tasking.manage_relocation` |
| 移库现场执行 / 异常管理 | `RELOCATION_PDA_ENABLED` | 执行：操作员角色及任务领取权限；管理：仓库管理员及 `tasking.manage_relocation` |
| 整容器移库 | `RELOCATION_CONTAINER_ENABLED` | 在相应移库申请或管理权限基础上另行启用 |
| 手工要货 / 审批 | `REPLENISHMENT_MANUAL_ENABLED` | 操作员 `tasking.request_replenishment`；管理员 `tasking.approve_replenishment`，并满足各自角色及任务权限 |
| 补货现场执行 / 过账重试 | `REPLENISHMENT_PDA_ENABLED` | 执行：操作员及任务领取权限；重试：仓库管理员及任务管理确认权限 |
| 阈值补货评估 | `REPLENISHMENT_MINMAX_ENABLED` | 仓库管理员及 `tasking.evaluate_replenishment`；策略须有效 |
| 出库需求补货 | `REPLENISHMENT_DEMAND_ENABLED` | 由已启用的业务链路和有效策略触发，不是普通用户自行开关 |

补货策略维护使用 `tasking.manage_replenishment_policy`，具备此权限不自动开启补货执行。当前 PDA 有订单收货页没有序列号录入控件，不把后端逐件序列号校验视为完整客户端流程。

POS 还款权限在当前实现中允许 `pos.add_poscustomerrepayment` 或 `pos.add_possale`；退货需要同时具备 `pos.add_posreturn` 和 `pos.add_posrefund`。具体收银、班次、撤销和对账边界见 [POS 使用手册](../pos_user_manual.md)。商城面向终端买家的操作见 [商城小程序使用教程](../sales-miniapp-user-guide.md)。

## 命名和兼容规则

- 企业岗位“仓库主管”需要管理作业时，系统角色使用 `WMS::仓库管理员`。
- 旧用户组名称“仓库主管”是 `warehouse_boss` 的兼容别名，会被识别为仓库老板。
- 权限决定能力，显式角色范围决定能够触达的数据；两者缺一时按拒绝访问处理。
- 同一普通账号只能有一种活动业务角色；仓库老板可在同一角色下配置多个仓库范围。
