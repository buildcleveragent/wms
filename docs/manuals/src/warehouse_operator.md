## 角色职责与权限

仓库操作员负责授权仓库内的现场收货、上架、拣货、复核及查询；移库和补货启用后，也按授权参与申请与执行。规范角色组为 `WMS::仓库操作员`，必须配置一个活动的仓库角色范围。

默认角色模板能力包括：仓库现场作业、无订单收货、退货出库、查看仓库运营报表、查看和领取任务，以及在满足货主授权时执行代货主出库。已有账号是否具备新增权限，以首页刷新后的能力和管理员确认结果为准。

以下能力不是默认权限：

- 商品 Excel 导入需要额外的商品导入权限，首页以服务端 `can_import_products` 能力为准。
- POS 收银、销售报表、对账、退款等需要独立 POS 权限，操作方法见专项 POS 手册。
- 仓库操作员不能确认货主订单、执行仓库管理员审核、调整角色权限或直接修改库存。

规范角色包含移库和要货申请权限，但申请、现场执行以及整容器移库分别受功能开关控制，默认并未开放。只使用首页实际出现且能够访问的入口；功能未启用时由管理员确认，不通过更换账号绕过。

## 班前检查

1. 使用本人账号登录仓库 PDA，核对用户名和所属仓库。
2. 检查设备网络、扫描头、电量和打印条件。
3. 刷新首页权限资料；代货主出库和商品导入入口只在服务端确认能力后开放。
4. 打开任务列表或仓库报表确认能够读取当前仓库数据。
5. 查看上一班交接，优先处理已领取、执行中或待复核任务。

## 有订单收货

1. 首页进入“收货（有订单）”，按任务号、来源单号或商品搜索。
2. 核对任务仓库和来源单据，点击“领取任务”；只有任务领取人可以登记收货。
3. 点击“开始收货”，逐行核对商品和计划数量。
4. 为每行选择当前仓库内的收货库位。
5. 普通商品填写当前行累计良品、破损和拒收数量，不是本次新增量。例如已登记良品 4 件、这次再收到 3 件，应改为累计 7 件。
6. 破损或拒收数量大于零时填写对应原因；需要追溯的商品填写批次号、生产日期和有效期。
7. 尚未结束该行时点击“保存收货数量”。超收必须填写差异原因；少收、全拒收或其他差异需要结束时，复点后填写差异原因并开启“结束此收货行”，再点击“保存并结束该行”。
8. 核对已登记、待处理和行完成状态。网络异常时保留原内容重试，看到“已确认此前收货记录”后不要再新增同一批数量。
9. 所有行处理完成后返回任务列表，确认任务状态和后续上架任务。

禁止事项：不得把其他仓库库位填入任务，不得用良品数量掩盖破损或拒收，不得为绕过追溯规则虚构批次和效期。

当前 PDA 有订单收货页尚无逐件序列号录入控件，不能用普通商品数量登记完成序列号商品收货。遇到这类任务应停止并交管理员安排已验证的作业入口；不得临时关闭商品序列号控制。

## 无订单收货：逐项录入

适用于现场已经取得货主授权、但系统没有可关联入库订单的收货。

1. 首页进入“收货（无订单）”，搜索并选择正确货主。
2. 搜索并选择供应商，然后进入商品录入。
3. 扫描或搜索商品，核对名称、编码、规格、条码和基本单位。
4. 选择收货单位，确认包装换算后的基本数量。
5. 录入数量、批次、生产日期和有效期；同一商品不同批次或效期必须分行。
6. 使用“添加”累加同批次数量；需要直接替换当前数量时使用“改为”。
7. 打开入库清单，逐行复核商品、基本数量、单位和追溯字段。
8. 点击提交并记录收货任务号；随后查询库存明细和汇总确认数量增加。

货主不明、商品不能唯一匹配、包装换算不清、应填追溯字段但现场无法提供或实物尚未复点时不得提交。

### 扫码未找到商品：GS1 辅助建档

此入口用于无订单收货选品，须具备无订单收货权限且所选货主在授权范围内，并由管理员配置查询服务；它与商品 Excel 导入的独立权限不同。

1. 确认已选择正确货主和供应商，再扫描完整标准贸易条码。系统先找本地商品，未命中符合格式的条码时才查询 GS1 资料。
2. 核对返回的名称、规格、品牌、厂家和条码与实物一致；查到资料不等于商品已在本系统建档，也不代表已收货。
3. 在“补齐信息并加入收货单”中选择有效商品分类和基本单位，录入以基本单位计算的本次收货数量。
4. 根据实物填写批次和效期信息。填写批次号会启用批次管理；填写效期信息时按提示补全效期基准、有效天数和相应日期，不能为通过校验随意填写。
5. 确认后系统建档或使用已有商品，并加入收货清单。返回清单复核后，仍需执行正式提交才增加库存。
6. 未收录、资料不符、缺分类/单位或服务不可用时，保留条码和提示交管理员维护。不要重复建档或使用其他商品代替。

## 无订单收货：Excel 批量入库

1. 先选择货主，再进入“Excel 批量入库”。
2. 下载当前货主的标准模板。模板包含可用商品、单位和换算参考，不得使用其他货主的模板。
3. 只上传 `.xlsx` 文件，文件不超过页面限制；不得修改必需列名、填入公式或混用其他模板。
4. 点击“上传校验并预览”。此步骤只校验，不增加库存；任意一行错误都会阻止整批确认。
5. 核对预览中的商品、包装换算后基本数量、批次、生产日期和有效期。
6. 确认无误后点击“确认并批量入库”。系统会生成无订单收货任务并立即增加库存。
7. 记录任务号，按需要查看、打印或导出收货单，再核对库存。

序列号控制商品当前不进入该批量流程；重复确认同一有效预览时，系统使用幂等控制避免重复入账。

## 上架作业

1. 首页进入“上架”，按任务号、来源单号或商品搜索。
2. 领取任务并点击“开始上架”；未领取任务不能登记上架。
3. 核对来源库位、商品和待上架数量。
4. 搜索并选择当前仓库内的目标库位，目标库位不能与来源库位相同。
5. “本次上架数量”填写增量，必须大于零且不超过待上架数量。例如计划 10 件、已上架 4 件，本次移 3 件应填 3，剩余为 3。按实际分次选择目标库位后点击“确认上架”。
6. 网络中断后保持该行原目标库位和数量重试；看到“已确认此前上架记录”表示原操作已保存，不再搬一次实物。
7. 所有行完成后，核对任务状态、过账状态、目标库位库存和来源库位变化。

## 移库申请与现场执行

### 提交申请

1. 功能启用后，从首页“移库”进入“申请移库”。确认当前仓库和货主。
2. 选择“库存层移库”，核对来源库存的商品、批次、库位、容器及可用数量，填写移库数量。
3. 选择目标库位；按实际需要选择目标容器，散件保持“目标散件”。目标必须属于本次仓库，来源和目标的库位、容器组合不能完全相同。
4. 仅在整容器功能已启用并确认整容器实物范围后选择“整容器移库”，选择来源容器、不同于来源的目标库位及可选父容器，不用它代替单品数量调整。
5. 填写原因，点击“提交申请”。在申请记录核对待审核状态，等待仓库管理员批准；本人待审核申请不再需要时可按页面执行取消。
6. 提交结果不确定时先刷新申请记录核对，不能反复提交同一需求。

### 执行已发布任务

1. 在移库列表打开任务，核对货主、仓库、来源、目标、计划数量及过账状态，点击“领取”后“开始”。
2. 按行扫描来源库位；有来源容器时扫描来源容器，再扫描商品或该行允许的容器码。
3. 有目标容器时扫描目标容器，再扫描目标库位；序列号商品还需逐件扫描序列号。
4. 填写本次增量，核对不超过剩余量，点击“确认移库”。每次保存成功后查看累计已完成量，再录下一次数量。
5. 全部行完成后确认过账成功，再核对来源减少、目标增加及容器位置。单次扫描成功不等于整任务已过账。
6. 扫描不符、实物短缺或目标不可用时停止搬运，在可操作任务中点击“报告异常”填写说明并通知管理员；操作员不能恢复异常、重试过账或整单作废。

网络失败时保留当前页原扫码内容重试。若系统提示原结果尚未确认，不改库位、商品或数量强行提交；已离开页面则先查任务完成量并由管理员协助核对原记录。

## 要货申请与补货执行

1. 手工申请功能启用后进入“要货申请”，从策略列表选择正确商品与目标拣货位。列表为空时由管理员维护有效补货策略。
2. 填写基本单位数量和真实申请原因，点击“提交申请”，在申请记录跟踪待审核、批准或驳回结果。审批未通过前不搬货。
3. PDA 补货功能启用后，从首页“补货”打开任务。任务来源可能为手工申请、阈值或出库需求；是否自动产生取决于已启用的策略。
4. 核对货主、仓库、来源库位、目标拣货位、商品、批次和计划数量，点击“领取任务”和“开始补货”。
5. 依次扫描/输入来源库位、商品码、目标库位；序列号商品逐件扫描序列号。填写本次补货增量后点击“确认补货”。
6. 每次确认后核对已完成量和剩余量，完成全部行后确认过账成功及两个库位的库存变化。
7. 网络失败保持原扫描内容重试；实物或库存异常保留任务号交管理员处理，操作员不自行重试过账或重建任务。

## POS 额外岗位交接

兼任收银员时，先确认已有独立 POS 权限，并按《POS 使用手册》开班后办理收银、赊账或客户还款。交班前核对现金、退款、赊账、还款和打印结果；尚未确认的还款必须保留原客户及原请求继续核对，不能交由新账号重复收款。仓库任务完成不能代替 POS 交班。

## 代货主出库

只有当前账号同时具有单一仓库操作员范围、代办出库权限和任务领取权限，且货主允许仓库代办时，才能执行本流程。

1. 首页进入“代货主出库”；入口不可见时刷新权限资料，仍不可见则联系管理员。
2. 选择已授权货主和客户。更换货主会清空客户和商品，应重新选择。
3. 未选择“新货主”时，按原货主直接销售；需要转货时先按下一节完成新货主和客户选择，再继续选品。
4. 搜索商品名称、仓库SKU编码或条码，核对原货主商品、包装、换算后的基本数量及可用库存。录入大于零的数量，按实际填写源单号、收件人、电话、地址、备注和代办原因。基本单价可留空，服务端取商品默认价；未维护售价时该代办路径允许零价，不适用于货主业务端标准开单的价格规则。
5. `CASH` 客户必须填写完整收件人、联系电话和收货地址。
6. 提交后记录订单号；系统按代办链路创建订单和对应拣货任务。
7. 网络异常时先查历史订单；看到“已恢复原代办订单”表示原请求已成功，不得再建一张。

### 先转给新货主，再销售给客户

1. 选择库存所属的原货主，再在“新货主（选填）”选择接收货权的货主。两方都须有效、授权当前仓库并允许仓库代办；新货主不能与原货主相同。
2. 重新选择新货主的有效客户。更换或清空新货主后，核对并重选客户；不能沿用原货主客户编号判断归属。
3. 在原货主商品中选品，核对“原货主 → 新货主 → 客户”的路线。客户销售单价和转货单价均按基本单位填写；转货单价不填时沿用本行销售单价，两者不能与箱价混淆。
4. 提交后同时记录销售订单号、转货单号和拣货任务号。建单只预留原货主库存；不能把“待转货”当成已完成货权转移。
5. 实物按原货主的预留库存、库位、批次和序列号拣一次；扫描原货主对应条码。全部拣货、复核后一次过账，完成原货主转出、新货主转入及客户销售出库。
6. 商品对应停用、同条码匹配多个商品或包装换算冲突时，停止提交并交系统管理员维护对应关系。过账失败先查原任务，不再建一张转货或另扣一次销售库存。

### 历史记录、统计与补打

在“历史出库单”按页面条件查原单，通过“查看任务”核对履约和过账，再按允许状态“重打出库单”。跨货主记录显示双方路线和转货单号。“出库统计”的日期和状态筛选应与查询问题一致；代办单已建、待处理、异常和已完成不能混作已实际出库。

## 退货出库：退货主或原供应商

本节是仓库向外退货，不是 POS 顾客退货。入口为首页“退货出库”，须有单一仓库操作员范围及退货出库权限。

1. 在“新建 / 详情”选择库存货主，搜索或扫描商品。同一条码跨货主有多个结果时，核对货主后选择。
2. 打开具体库存，选择实际库位、批次、效期、容器及序列号；不能只按商品汇总数量退货。
3. 分别填写“正常退货”“已登记破损”和“现场发现破损”数量，均按基本单位录入、最多四位小数。正常与现场发现破损合计不能超过可用量，原有破损不能超过已登记破损量；已分配、锁定量不参与退货。
4. 选择“退给货主”或“退给供应商”。退供应商只能使用所选批次共同且可靠的原供应商来源；来源不明时退货主，不同供应商分别建单。
5. 填写必填退货原因，核对接收方和逐行数量，可先“保存草稿”。本人草稿可以编辑或删除。
6. 点击“确认退货”，在二次确认中复核货主、接收方和数量。成功后立即扣减库存，单据为“已完成”，不再走销售审批或另建拣货任务。
7. 结果不明时保留原账号、仓库和设备数据，点击“继续确认结果”恢复原请求；不要重建退货单。版本或库存已变化时刷新原记录并交接处理。
8. 确认错误需撤销时，仅由原操作员打开本人已完成单，确认货物仍在仓库或已实际退回，填写冲销原因后“整单冲销”。系统恢复原库存维度，现场发现破损仍恢复为破损；本流程不支持按行冲销。
9. 在“退货记录”“退货统计”查询、导出 Excel。统计按确认和冲销各自的操作日期计入，净退货为退货减冲销；跨日冲销不改写原日实绩，不同基本单位分别汇总。

日期查询默认当天，统计/导出最多 366 天；导出超过 50000 个事件行时缩小范围。冲销因库存维度或成本层变化被拒绝时交管理员核对，不能手工补库存。本功能只记录库存退货，不处理退款、结算或货权转移。

## 商品档案导入与导出

具备独立商品导入权限时，首页“商品导入”可使用当前 `.xlsx` 模板，单次最多 1000 条、5 MB。数量为空或零时仅建档；正数数量还需要无订单收货权限，并选择已配置有效默认收货库位的仓库。核对结果中的“自动收货完成”任务号，不能对同一批商品再做一次无订单收货。商品、字典或自动收货任一错误会回滚整批。

基本单位须预先在后台创建并启用；模板无需填写单位类型和小数位。导入跳过既有商品不等于更新成功；按返回原因处理，不能依靠反复上传覆盖旧资料。

商品导出需商品查看权限及可导出的货主范围，不因拥有收货权限自动开放：

- “商品导出”：选择单个货主后下载商品及包装档案。
- “全部商品档案导出”：直接下载当前权限范围内全部货主的商品及包装，不代表全系统全部数据，也不受导入的 1000 行上限限制。
- “无标准条码导出”：用于排查标准贸易条码缺失；没有标准贸易条码不等于没有其他可用条码，不得据此批量覆盖历史标识。

下载后核对货主、商品数及包装记录；设备提示文件已下载但打不开时在文件管理中查找。导出不修改库存，导出工作簿也不能未经核对直接作为导入模板。

## 拣货、复核与过账

### 拣货

1. 进入“拣货”，打开当前仓库的活动任务并核对任务号、货主、状态和过账状态。
2. 按任务行到指定库位取货，核对商品、批次、效期和计划数量。
3. 扫描商品条码或按页面允许方式录入，提交本次数量并观察累计完成量。
4. 所有任务行完成后点击“完成拣货”。未拣完、商品不匹配或数量超计划时系统会拒绝完成。
5. 标准出库完成拣货后进入复核流程；实物与任务必须一一对应交接。

### 复核和库存生效

1. 复核人员进入“复核”，打开待复核任务。
2. 核对任务号、货主、商品、计划量、完成量、批次和库位。
3. 标准出库必须由不同于拣货人的操作员独立复核；系统允许的代办特殊流程按页面明确提示执行。
4. 发现差异时先复点实物，不得用“复核通过”跳过差异。
5. 全部一致后执行复核，通过后确认来源拣货任务已成功过账，库存状态为 `POSTED`。

扫码异常时停止当前行：商品不匹配应核对库位和条码；库存不足不得换货主、批次或库位凑数；重复扫码以页面累计量为准并在完成前修正。

## 库存、报表与交接

- “查询/公司库存汇总”用于查看在库、可用、已分配、锁定和损坏数量；判断能否出库必须看可用数量。
- “报表/仓库统计”按月份或日期范围查看货主维度的入出库单量和数量，并可进入明细。
- 发现负数、可用量大于在库量、同一批次异常分散或任务已过账但库存未变化时，立即截图并上报。

- [ ] 已领取任务已经完成或明确交接。
- [ ] 已拣实物与待复核任务一一对应。
- [ ] 收货、上架和出库的任务号已经记录。
- [ ] 退货确认、冲销和跨货主转货均已核对原单、实物及库存结果。
- [ ] 移库、补货的未完成量、过账状态和现场实物已明确交接。
- [ ] 兼任 POS 岗位时已核对未确认收付款并按专项流程交班。
- [ ] 未解决的库存、条码、设备或网络异常已经上报。
- [ ] 已退出账号，设备归位并充电。
