## 角色定位与权限边界

系统管理员是后台管理职责，不是 `UserRoleScope` 中的业务角色。超级管理员通过 Django `is_superuser` 获得全局访问；其他后台账号仍必须通过职员状态、显式业务角色范围、规范角色组和经过审批的辅助权限组合授权。

系统管理员负责账号、角色范围、基础资料、配置和审计，不代替业务员开单、货主管理员审核、仓库管理员确认或操作员现场作业。

## 五类岗位开通对照

| 发放的用户手册 | 系统角色／账号方式 | 范围与入口 | 交付前核对 |
|---|---|---|---|
| 货主端管理员 | 货主管理员；`WMS::货主管理员` | 单货主；货主业务端 | 订单／到货／客户退货审核、出入库记录、预警管理、账单 |
| 货主端业务员 | 货主业务员；`WMS::货主业务员` | 单货主；货主业务端 | 开单、导入、入库申请、客户退货申请、本人单据跟踪 |
| 仓库端操作员 | 仓库操作员；`WMS::仓库操作员` | 单仓库；仓库 PDA | 领取、实物作业、客户退货验收、实盘；不提供管理审批 |
| 仓库管理员 | 仓库管理员；`WMS::仓库管理员` | 单仓库；Web 及已开放 PDA 管理页 | 入出库确认、批次／上架审核、盘点发布／审核／过账 |
| 系统管理员 | 超级用户或经审批的后台权限组合 | 全局或明确授权范围；Web 后台 | 账号、资料、配置和审计权限符合职责 |

培训名称“货主端管理员”“货主端业务员”“仓库端操作员”不创建新的权限组，仍使用上表系统规范名称。仓库老板经营看板另有扩展指南，不作为仓库管理员作业手册发放。

## 用户和角色范围管理

### 新建用户

1. 进入“系统 → 用户”新增账号，设置唯一用户名、姓名、联系方式和初始密码。
2. 设置账号为有效；只有需要登录 Web 后台的账号才启用职员状态。
3. 普通业务用户不要勾选超级用户。
4. 在“用户角色范围”新增一条活动范围，选择业务角色及对应货主或仓库。
5. 保存后系统自动同步对应规范角色组，检查“系统规范角色组”显示是否正确。
6. 使用该角色测试账号验证入口、菜单、允许操作和数据隔离，再安全交付初始密码。

### 范围规则

- 仓库操作员、仓库管理员只能配置一个活动仓库范围。
- 货主业务员、货主管理员只能配置一个活动货主范围。
- 仓库老板可以为同一角色配置多个活动仓库范围。
- 同一普通用户不能同时启用多个业务角色。
- 超级管理员使用全局范围，不得再配置业务角色范围。
- 用户模型中的旧 `owner`、`warehouse` 字段仅供 POS、商城等兼容模块使用，不决定 WMS 角色和数据范围。

## 规范角色组与“仓库主管”说明

系统规范角色组包括：

- `WMS::仓库操作员`
- `WMS::仓库管理员`
- `WMS::仓库老板`
- `WMS::货主管理员`
- `WMS::货主业务员`

规范角色组名称固定，由角色范围自动同步，不应手工改名或删除。需要调整规范权限模板时应通过代码、迁移和测试发布，不能在生产环境临时修改后不留记录。

“仓库主管”是旧兼容组名，当前会识别为仓库老板角色。企业内部的作业主管若要确认单据、管理任务，应配置 `WMS::仓库管理员`，不能创建或沿用名为“仓库主管”的组。

## 额外权限管理

- 商品 Excel 导入、POS、计费、报表导出、商城运营等不一定属于规范角色默认权限，应使用经过审批的辅助权限组。
- 优先使用权限组，不给个人账号长期追加零散权限。
- 删除、直接库存调整、计费规则、退款、支付状态、批量导入和用户授权属于高风险权限。
- 每次权限变化后检查审计事件，并使用边界数据验证不能访问其他货主或仓库。
- 不得用额外权限绕过显式角色范围；权限授予能力，角色范围限制能够触达的数据。

## 移库、补货的启用与岗位分工

1. 先与仓库确认需要开放的能力：移库申请/管理、移库现场执行、整容器移库、手工要货、补货现场执行、阈值补货或出库需求补货。这些开关默认关闭，不能仅凭看到权限名称就宣布功能已可用。
2. 检查仓库操作员规范组的申请及任务领取权限，仓库管理员规范组的审核、移库管理和补货策略权限；岗位不得混配。既有组权限有定制时，以实际授予结果为准。
3. 由部署负责人按已批准范围启用对应功能；本手册不提供直接修改生产环境的操作命令。
4. 补货启用前，由仓库管理员核对有效策略、目标拣货位、来源库区、单位换算和库存；整容器移库另外核对容器层级及位置。
5. 使用实际岗位账号刷新首页权限资料，分别确认操作员能申请/领取/执行、管理员能审核/管理且不能代替移库、补货操作员扫码；再验证未授权仓库和关闭的功能不可使用。
6. 明确失败交接人：操作员记录实物和扫描状态，管理员处理恢复、作废或原任务过账重试，系统管理员排查配置和故障。

## 基础资料维护顺序

建议按以下顺序建档：

1. 货主。
2. 仓库、子仓、库位及货主—仓库授权关系。
3. 商品分类、品牌、商品、基本单位、辅助单位和包装换算。
4. 客户、供应商、承运商、司机和车辆。
5. 入库、出库、分配、拣货和效期策略。
6. 计费规则、阶梯和账期。
7. 用户、显式角色范围及必要的辅助权限。

货主商品编码和仓库SKU编码是稳定主数据，创建后不得修改。标准贸易条码是 GTIN/EAN/UPC 等贸易条码的正式显示名称；条码、包装条码和外部系统商品编码通过独立的标识维护入口追加历史记录，不直接覆盖旧值。基本单位是库存记账单位。修改包装换算、批次/效期控制或停用商品前，必须确认没有未完成单据、任务和库存影响。

### 共享客户与货主业务资料

1. 新增客户前先查名称、电话及地址，确认是否已有同一终端客户档案。通用档案保存名称、联系方式、地址等资料；各货主的客户编号、外部编号、业务员及配送资料保存在“货主客户关联”。
2. 新增客户时先选货主，再选其有效业务员；下拉项来自该货主的活动“货主业务员”角色范围。未选货主、货主无有效业务员或无权维护该货主时，业务员列表为空。更换货主后重新选择，不能使用其他货主业务员。
3. 同一客户需要服务多个货主时，由具有全局范围和相应权限的管理员，在客户详情的关联明细新增各货主关系；每个货主的客户编号及非空外部编号须唯一，每个货主与同一客户只保留一条关联。
4. 普通货主后台账号仅按授权维护自己可见的业务关联，不能修改共享通用档案、跨货主新增关联或删除共享客户。需要改名称、地址或停用通用档案时交全局管理员评估对其他货主的影响。
5. 停用某个货主关联与停用共享客户含义不同；前者停止该货主使用，后者影响全部关联。商城买家也必须有当前货主的有效客户关联。
6. 不使用客户旧 `owner/code/salesperson` 字段判断当前业务归属，不因同名或同电话自动合并历史档案。发布共享客户迁移后先核对既有客户关联、业务员、历史订单及报表，再交付账号使用。

### 代办转货、退货权限与商品对应

- 代办转货需要双方货主均启用仓库授权和仓库代办，并有新货主的有效客户关联。原货主与接收货主商品应有明确来源绑定，核对基本单位、批次/效期/序列号控制及包装换算，不能仅凭商品同名或相同条码自动认定对应。
- 既有映射与历史转货会参与永久来源保护，停用映射或取消订单不解除绑定。无可用目标档案时由系统受控建档并绑定；接收货主已有同条码时先核实明确对应，不复制冲突档案。多来源、停用对应、资料差异或包装冲突需保留提示，由全局管理员核查后再继续。
- 接收商品的名称、规格、品牌型号、基本单位及追踪规则受保护，双方已有包装单位与比例同样受保护。来源描述更正由受控流程同步，历史单据保留快照；新增包装从来源侧同步，接收方经营价格独立维护。计量规则确需变化时新建来源商品，不直接改旧商品或已预留转货单。
- 历史资料异常交部署／维护负责人生成只读检查报告，明确影响范围、价格按何种单位计价和审批依据后处理。用户后台操作不能替代迁移、审计或受控修复，不在手册中复制真实客户案例及修复命令。
- 仓库管理员和货主管理员默认模板包含 `outbound.view_assistedownershiptransfer`；这只授予按范围查看转货证据，不授予改写或删除。
- PDA 退货需单仓操作员角色和 `outbound.process_pda_return`。已有组升级是否补齐权限须单独核对；默认组同步保留原权限，采用完整默认模板时才由部署负责人按既有流程执行 `sync_wms_role_groups --ensure-defaults`，定制环境只补批准权限。
- 发布时通过正常迁移流程部署共享客户、代办转货、PDA 退货等当前迁移及对应前端。不清空业务库存、不伪造迁移状态、不补造成本层；退货冲销因成本层不完整被拒绝时先排查。

### 到货、客户退货与盘点权限核对

1. 到货预报由货主业务员建单／提交、货主管理员审核、仓库管理员确认并发布；分批验收由操作员填本批数量，仓库管理员审核入账及上架。核对仓库管理账号的到货管理权限，不能以旧累计收货培训替代分批验收说明。
2. 客户退货由有申请权限的货主岗位从原销售单发起，货主管理员审核，仓库管理员确认接收或关闭余量，仓库操作员领取并验收；核对各岗位对应的申请、审批、管理、验收权限。专用验收页允许原经办人重试未入账批次，不扩大为普通任务过账权限。
3. 盘点管理使用仓库任务管理确认能力及有效数据范围，操作岗位使用任务领取能力。验收“草稿不冻结、发布冻结、操作员盲盘隐藏账面与差异、复盘延续冻结、有差异审核后过账、失败保留冻结”等控制点。
4. 货主端“出入库记录”仅对具备库存及运营查看能力的货主管理员开放，导出还需运营导出能力；业务员继续使用“入出库履约”。库存预警管理能力与查看能力分别验证。
5. 旧组不会因为手册更新自动新增权限。按经审批的默认模板或定制权限配置交付，使用角色测试账号分别核对允许操作、拒绝操作及范围隔离。

### 商品标识历史维护

- 同一货主内，货主商品编码、仓库SKU编码、全部商品条码、包装条码和外部系统商品编码共享唯一命名空间；比较时忽略首尾空格和大小写。不同商品不得交叉复用，跨货主可以复用。
- 新厂家码、新旧包装并存或箱规变化时使用“新增”操作创建记录。新箱码或包装条码必须选择当前商品下启用且未删除的包装层级，系统会固化当时的基础单位换算快照。
- “设为主码”只改变兼容字段的当前投影，不删除、不停用旧码。停用、软删除、尚未生效、已过期或关联无效包装的记录不能设为主码。
- “退役”会停止普通搜索和扫码；“重新启用”仅恢复未软删除且仍满足有效期、包装和商品状态的记录。普通删除等同退役，不执行硬删除。
- 历史标识退役、过期或软删除后仍永久占用，不能重新分配给其他商品。业务商品和带历史的标识禁止硬删除。
- 普通搜索只使用当前有效标识；历史审计应在商品条码或外部标识维护入口中按记录查询。
- 批量维护使用当前“商品条码维护”和“外部标识维护”工作表，操作值为 `ADD`、`SET_PRIMARY`、`RETIRE`、`REACTIVATE`。导入为整批事务，任意行失败时不得保留注册项、主值投影或旧主码降级。

例如厂家换箱码时，新增一条箱码并选择对应包装，再按需要设为主码；不要覆盖旧条码或把旧包装换算改成新箱规。扫码抽查新旧箱码各自的基本数量，确认历史商品仍可追溯。

### GS1 辅助建档的准备与核对

1. 在系统设置维护已批准的 GS1 查询服务配置，按配置入口保存凭据，不把凭据抄入手册、工单或截图。
2. 确认操作员具有无订单收货权限，所选货主处于有效授权范围，并有可选的有效分类、基本单位。
3. 在无订单收货选品中核对“本地优先查询 → GS1 候选 → 补齐分类、单位和追溯信息 → 加入收货清单”的结果。查到资料不代表已入库，正式提交收货清单后才核对库存。
4. 服务未收录、资料不符、标识冲突或配置异常时先核对本地商品；必要时由有权限人员人工维护主数据，不能让操作员复用其他商品编码。
5. 传统 PDA 有订单收货页缺少序列号输入；到货申请分批验收有序列号字段。按实际任务与表单分别培训，不把后端支持泛化成所有客户端都支持，也不关闭追溯控制来适应旧页面。

## Excel 导入与批量配置

- 使用系统当前页面下载的模板，不复用历史模板。
- 商品导入按权限和数据范围校验，整批原子处理；任意错误会阻止整批写入。
- 标识维护导出包含包装、单位和基础单位换算快照；历史快照仅用于审计，新增包装条码的换算值由所选包装层级生成。
- 公式、重复标识、其他货主数据、无效扩展名和超限文件会被拒绝。
- 仓库SKU编码由系统规则生成时，用户模板中的仓库SKU编码不作为覆盖依据。
- 商品导入最多 1000 条、5 MB；数量为空或零只建档，正数数量会按所选仓库默认收货库位自动收货，另须无订单收货权限。任一商品、字典或收货错误回滚整批；结果中已经自动收货的行不能再次入库。
- 基本单位必须预先创建并启用，单位类型和小数位不由导入模板指定。既有商品跳过不等于覆盖更新。
- “全部商品档案导出”覆盖当前权限范围的货主商品和包装，不受导入行数上限约束；与单货主导出、缺标准贸易条码导出的用途分别说明。导出需要商品查看权限与有效可导出范围。
- 无订单批量入库、一件代发导入与商品主数据导入用途不同，禁止混用模板。
- 导入后保存结果、审计记录和抽查样本，不能只依据前端提示判断成功。

## 商城、POS 与计费管理边界

- POS 收银、仓库内 POS 客户、赊账还款、退货、班次和打印配置按《POS 使用手册》管理；POS 销售通过统一任务和过账链路影响库存。兼容仓库字段必须与有效授权范围一致，不能通过改旧字段跨仓收银。
- 商城上架、支付、退款、评价审核和批量配置按商城专项指南管理；商城买家不配置 WMS 业务角色。
- 计费规则、账期锁定、开票和解锁属于高风险财务操作，应保留审批依据和审计记录。
- 系统管理员可以维护配置和排查异常，但不能代替货主或仓库确认业务事实。
- 打印页过期时引导用户从原单重新打印；修改密码后旧打印凭据也会失效。打印成功提示不代表纸张已输出，不能因打印失败重复收银或收货。
- 送货单的基本单位／包装单位选择只改变打印显示；新单使用开单时的包装快照，旧单无可靠比例时仅按基本单位。预览核对数量、单价及金额，不通过改商品箱规修复历史打印。

## 审计、账号安全与故障处理

1. 在审计事件和 Admin 日志中按用户名、时间、模块和操作类型查询。
2. 发现异常新增、修改、删除、导入、导出或授权时，先停用可疑账号并保留日志。
3. 遗忘密码走重置流程；管理员不得读取、传播或在群聊中发送明文密码。
4. 角色范围冲突、缺失规范组或范围与组不一致时，账号应保持拒绝访问，修正配置后再验证。
5. 库存、订单、支付和账单异常应先保全事实记录，不直接改数据库或删除流水。
6. 登录过频时核对对应入口和时间，按限流提示等待；不通过反复尝试或更换入口绕过限制。临时网络故障与账号失效分别处理，切换账号后重新验证数据范围。

服务器部署、数据库备份恢复、域名证书、服务启停和版本回滚属于独立运维流程，本手册不授权在生产服务器直接操作。

## 用户开通验收表

- [ ] 用户名唯一，姓名和联系方式正确。
- [ ] 账号有效，职员/超级用户状态符合用途。
- [ ] 只有一种业务角色，货主或仓库范围正确。
- [ ] 规范角色组已自动同步，没有无关高权限组。
- [ ] 老板多仓范围逐仓验证，其他角色没有多活动范围。
- [ ] 登录入口、菜单和岗位一致。
- [ ] 不能查看其他货主或仓库数据。
- [ ] 高风险按钮只对授权人员可见且服务端会再次校验。
- [ ] 移库、补货各项开关与岗位能力一致，已说明当前 PDA 序列号收货限制。
- [ ] 共享客户关联及业务员正确，转货查看和退货办理权限已按岗位核对。
- [ ] 到货、客户退货和盘点已按申请、审核、实物作业及入账职责分别核对。
- [ ] 转货商品来源保护、包装快照及五类岗位手册发放均已说明。
- [ ] 初始密码已安全交付并要求首次修改。
