## 角色定位与权限

仓库管理员负责授权仓库的单据确认、任务控制、库存监督和运营异常处理。规范角色组为 `WMS::仓库管理员`，必须配置一个活动的仓库范围。

本册也适用于企业内部称为“仓库主管”的作业管理岗位，但系统授权必须选择“仓库管理员”。旧用户组名称“仓库主管”属于仓库老板的兼容别名，会被识别为只读经营角色，不能用于授予仓库管理权限。

默认权限覆盖仓库运营报表、入出库单查看与确认、任务查看与管理、库存明细/汇总/流水/快照查看，以及移库管理、补货策略管理和申请审核。移库、手工要货、PDA 执行及自动补货分别由功能开关控制，默认关闭，须按实际启用范围使用。计费、商品导入、POS 和系统权限管理均不是仓库管理员默认能力，需要单独审批授权。

## 每日工作顺序

1. 登录 Web 控制台或 Django Admin，确认当前账号的仓库范围。
2. 检查待货主审核、待仓库确认、保留、待发布、执行中、待复核和过账失败数量。
3. 处理满足条件的入出库确认，发布任务并跟踪现场执行。
4. 班中查看库存分配、任务完成率和仓库运营报表。
5. 班后处理未过账、库存差异和失败任务，形成下一班交接。

## 入库单确认与收货监督

1. 进入“入库 → 入库单”，筛选当前仓库待确认单据。
2. 核对货主、仓库、供应商、预计到货日期、商品、数量和追溯要求。
3. 货主尚未审核、仓库不匹配或基础资料不完整时不得确认。
4. 满足条件时执行“仓库管理员：确认通过”；不能接收时填写真实原因并驳回。
5. 确认后检查收货任务是否生成并具备发布/领取条件。
6. 跟踪有订单收货的良品、破损、拒收记录以及后续上架任务。
7. 对无订单或 Excel 批量入库，按任务号核对库存明细、汇总和流水，不能只看前端成功提示。
8. 核查差异收货行是否有破损、拒收或收货差异原因。普通商品收货是累计数量，上架是本次增量，培训和复核时不能混用。
9. 收货完成不代表入库链路全部结束；确认相关上架任务均已过账，再核对入库单关闭结果。当前 PDA 有订单收货页没有序列号录入控件，序列号任务须安排已验证的入口处理，不能关闭追溯控制强行收货。

## 标准出库确认与任务发布

1. 进入“出库 → 出库单”，筛选当前仓库待确认订单。
2. 确认订单已经提交并由货主管理员审核通过；草稿、待货主审核、已取消或已关闭订单不能确认。
3. 核对货主、仓库、客户、地址、商品、数量、价格审核结果和库存分配。
4. 货主审核通过时系统会冻结库存并生成 `RESERVED` 拣货任务；检查是否只有一个有效任务且已经完整分配。
5. 执行“仓库管理员确认（审核 + 生成拣货任务）”，系统把合法的保留任务发布为 `RELEASED`。
6. 在任务列表确认 PDA 已可见，再安排操作员领取。

系统已经停用“仓库管理员一键确认（货主+仓库审核）”。标准出库必须保留货主管理员审核和仓库管理员确认两个独立控制点。

## 驳回、取消和库存释放

1. 仓库条件不满足时执行仓库管理员驳回，并填写可追踪的处理说明。
2. 系统只允许在相关拣货任务尚未开始、没有执行数量时取消任务并释放冻结库存。
3. 驳回或取消后核对订单状态、任务状态、库存已分配量和可用量。
4. 任务已开始、已完成或已有扫描数量时，先隔离实物并按异常流程处理，不能强行删除任务或订单。
5. 货主业务员撤回和货主管理员取消同样必须经过库存释放校验；发现冻结量未释放立即停止后续出库。

## 任务发布、审核与过账

- 发布前检查任务有有效明细、计划数量大于零、仓库和单据来源一致。
- 已发布未领取任务应明确责任人；执行时间过长时联系现场核对实物状态。
- 任务完成后检查复核状态。标准出库的拣货人与复核人必须分离。
- 管理端审核或过账只用于满足状态条件的任务；未审核通过的任务不得过账。
- 过账失败时保留任务号、错误信息、扫描记录和业务单号，不得通过重建任务绕过原失败。
- 取消任务前确认是否发生实物移动；已经移动的实物先隔离并形成交接记录。

## 库存查询、调整与盘点控制

1. 在库存明细和汇总中按仓库、货主、商品、库位、批次筛选。
2. 使用交易流水、过账分录和快照追溯库存增减来源。
3. 快速入库/出库调整只用于经过批准的差异修正，不用于日常收发货。
4. 调整前保存盘点或差异依据，填写真实原因和关联单号；调整后同时核对明细、汇总和流水。
5. 盘点差异必须复盘确认后处理，禁止为追平报表直接改库存明细。
6. 发现负库存、冻结量异常、过账失败或明细与汇总不一致时停止相关商品作业并升级处理。

## 移库审批、下发与异常处理

1. 确认移库申请/管理及现场执行已启用，管理员和操作员分别使用自己的角色账号。仓库管理员管理任务，不代替操作员领取和扫码。
2. 在仓库 PDA“移库 → 移库管理”查看待审核申请，核对货主、仓库、来源库存或容器、目标库位、数量和原因；不符合条件时点击“驳回”并填写原因。
3. 条件满足后点击“批准”，返回任务列表确认已生成可领取任务。同仓库库存层移库可以更换容器；整容器移库需单独启用且必须更换库位，审批时核对全部容器内实物。
4. 需要由管理岗位直接组织移库时，在“直接下发移库任务”选择仓库、货主、模式、来源、目标、数量和原因，再点击“直接发布”；这属于移库任务，不替代出库单的货主审核。
5. 跟踪操作员分次扫描的累计量和剩余量；整任务过账成功后，核对来源、目标库存及容器位置。审批或扫描成功都不能代替过账核对。
6. 操作员报告异常后，先确认实物位置和已搬数量，处理原因，再在原任务点击“恢复”；需要终止时说明原因执行“整单作废”，并核对预留释放及实物交接。已过账任务不能直接作废。
7. 过账失败时保留原扫描记录，处理库位、库存或系统原因后，在原任务点击“重试过账”。失败未解决前不重建任务、不重复搬运。

## 要货审核与补货监督

1. 由管理员维护补货策略中的仓库、货主、商品、来源库区、目标拣货位、补货单位及阈值。策略管理权限不等于自动补货已启用。
2. 手工要货启用后，在“要货申请”的申请记录查看待审核行，核对目标拣货位、基本单位数量和原因。
3. 来源库存和规则满足时点击“批准”，核对生成的补货任务；不满足时查明原因，不能把审批失败当成已批准或另建重复申请。驳回时填写说明。
4. 阈值和出库需求补货按各自开关及策略运行。核对现有在途补货、可用来源库存和任务来源，避免重复安排人工搬货；后台策略评估产生的任务是否自动发布以策略配置为准。
5. 安排操作员领取并按任务扫描来源库位、商品和目标库位，跟踪剩余量。管理员不代替操作员扫码。
6. 任务完成后核对过账与库位库存。PDA 执行已启用且任务允许重试时，由管理员在原任务执行“重试过账”；其他异常先保存证据交接处理。

## 代办转货和退货出库监督

- 跨货主代办按“原货主 → 新货主 → 客户”核对，原货主库存先预留，拣货与复核完成后统一过账。核对转货单、销售单、任务及原货主转出/新货主转入/销售出库流水，不能把中间转入量当成仓库新增实物收货，也不能重复下发扣库任务。
- 取得查看权限并可登录后台时，可在“代办货权转移单”查看本仓库只读证据；商品对应由系统管理员维护，不在审核中临时改库存归属。
- PDA“退货出库”由有权限的仓库操作员办理，确认即扣库存，不需要仓库管理员审批。规范仓库管理员角色不因此自动获得退货办理或查询入口；由经办人提供记录、统计及退货单号，管理员按本职权限核对库存流水。
- 监督本人草稿、本人确认与整单冲销的责任边界；冲销前核实实物，现场发现破损冲销后仍为破损。不借用经办人账号，不删除流水代替冲销。
- 退货统计按确认/冲销各自日期、各基本单位核对；仓库退供应商不等于已经退款或完成供应商结算，财务另行处理。

## POS 岗位与打印交接

管理仓库不自动取得收银、退货或客户还款权限。兼任 POS 管理时按《POS 使用手册》核对开班、销售、退款、赊账、还款和交班差异；收付款失败或结果不明必须先恢复原记录。销售已完成但打印失败时安排补打，不能要求收银员重新结账。仓库库存监督与 POS 现金实点应分别留下核对结果。

## 报表、导出与额外财务权限

- 默认可查看当前仓库运营报表并按授权导出，核对入库、出库、任务和库存趋势。
- 计费总览、收入和账单不是规范仓库管理员角色的默认权限；只有额外授予仓库财务权限时才可使用。
- 取得财务权限后，按货主、仓库和账期核对费用来源、收费类型和账单行；不得直接改总额掩盖差异。
- 导出文件包含业务范围数据，应按公司数据安全要求保存和传递。

- [ ] 已完成未复核、未审核或未过账任务已经处理。
- [ ] 取消、撤回和驳回后的冻结库存已经释放。
- [ ] 无异常负库存、锁定量、残次数或范围外数据。
- [ ] 过账失败、库存差异和额外财务异常已经登记。
- [ ] 已启用的移库、要货和补货任务已核对审批、剩余量、实物位置及过账状态。
