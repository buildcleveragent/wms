# 金桥融通WMS仓库管理员操作手册

**文档版本：** V2.2

**适用系统版本：** 2026-10-17 当前工作区业务基线

**适用对象：** 仓库管理员

**正式权限组：** `WMS::仓库管理员`

**主要入口：** Web 控制台 / Django Admin，必要时使用仓库 PDA

**文档状态：** 交付版

> 本手册按当前业务代码、权限校验、客户端页面和自动化测试契约编写。实际菜单由角色、权限和显式数据范围共同决定。

## 使用范围

| 项目 | 本角色要求 |
|---|---|
| 角色 | 仓库管理员 |
| 正式权限组 | `WMS::仓库管理员` |
| 主要入口 | Web 控制台 / Django Admin，必要时使用仓库 PDA |
| 数据范围 | 一个明确的仓库范围 |

本册可独立用于培训和日常操作，不要求先阅读合订版。涉及其他岗位时，只说明交接点，不授权本角色代替其他岗位操作。

## 登录、账号与通用安全

### 首次登录

1. 从系统管理员处取得正式入口、用户名和初始密码。
2. 打开本岗位对应的应用或 Web 地址，输入用户名和密码。
3. 登录后核对显示姓名、业务角色以及货主或仓库范围。
4. 首次登录立即进入“我的 → 修改密码”或 Web 右上角密码修改入口。
5. 如果能够登录但没有菜单，不要借用其他账号，记录用户名、入口和页面截图并联系系统管理员。

### 登录失效与切换账号

1. 使用管理员提供的正式入口；客户端的服务地址由部署配置决定，不在登录页自行改接其他服务器。
2. 使用过程中客户端会尝试续期登录。临时断网或服务器繁忙时先检查网络，恢复后重新查询当前单据；不能把网络故障当成业务未提交。
3. 明确提示登录失效并返回登录页时，重新登录本人账号，再核对角色、仓库或货主范围。
4. 看到“登录账号已变化”或“登录状态已变化”时停止当前操作，刷新页面并重新选择业务对象。旧账号的页面结果不能作为新账号继续操作的依据。
5. 连续登录过频时按提示等待，不连续点击；仍不能登录则联系管理员检查账号。

### 账号和数据范围

- 一人一号，不得共用账号或把密码留在 PDA、电脑旁。
- 角色决定能够执行什么操作；显式角色范围决定能够操作哪个货主或仓库的数据。
- 普通 WMS 用户只能启用一种业务角色。除仓库老板可授权多个仓库外，其他角色只能有一个活动范围。
- 超级管理员使用全局权限，不设置业务角色范围；超级管理员账号不得用于日常开单、审批和现场作业。
- 离职、调岗、合作终止或设备丢失后，应立即停用账号并保留审计记录。

### 通用操作原则

1. 操作前核对货主、仓库、客户、商品、批次、库位和单据号。
2. 扫码后必须核对系统命中的商品名称和规格，不能只凭提示音继续。
3. 审核、复核、过账、取消和库存调整会改变业务状态或库存，提交前必须再次确认。
4. 系统提示成功后再离开页面；网络中断时先查询原单状态，确认未成功后才重试。
5. 禁止通过直接修改库存明细来代替正常收货、上架、拣货、复核、盘点或调整流程。
6. 页面入口可见不代表账号一定有执行权限；最终以服务器返回的角色、权限和数据范围校验为准。

### 修改密码与退出

1. 修改密码时输入原密码、新密码和确认密码；新密码必须通过系统安全校验。
2. 修改成功后退出，并用新密码重新登录验证。
3. 当班结束或共用设备交接前必须从“我的”或用户菜单执行退出，不能只关闭屏幕或浏览器。
4. 切换账号前先记录尚未确认的单号、任务号及收付款结果；下一位人员使用自己的账号重新打开业务页面，不接着提交上一账号遗留的内容。

## 角色定位与权限

仓库管理员负责授权仓库的单据确认、任务控制、库存监督和运营异常处理。规范角色组为 `WMS::仓库管理员`，必须配置一个活动的仓库范围。

本册也适用于企业内部称为“仓库主管”的作业管理岗位，但系统授权必须选择“仓库管理员”。旧用户组名称“仓库主管”属于仓库老板的兼容别名，会被识别为只读经营角色，不能用于授予仓库管理权限。

默认权限覆盖仓库运营报表、入出库单查看与确认、任务查看与管理、库存明细/汇总/流水/快照查看，以及移库管理、补货策略管理和申请审核。移库、手工要货、PDA 执行及自动补货分别由功能开关控制，默认关闭，须按实际启用范围使用。计费、商品导入、POS 和系统权限管理均不是仓库管理员默认能力，需要单独审批授权。

## 每日工作顺序

1. 登录 Web 控制台或 Django Admin，确认当前账号的仓库范围。
2. 检查待货主审核、待仓库确认、保留、待发布、执行中、待复核和过账失败数量。
3. 处理满足条件的入出库确认，发布任务并跟踪现场执行。
4. 班中查看库存分配、任务完成率和仓库运营报表。
5. 班后处理未过账、库存差异和失败任务，形成下一班交接。

## 入库单确认与收货监督

1. 进入“入库 → 入库单”，筛选当前仓库待确认单据。
2. 核对货主、仓库、供应商、预计到货日期、商品、数量和追溯要求。
3. 货主尚未审核、仓库不匹配或基础资料不完整时不得确认。
4. 满足条件时执行“仓库管理员：确认通过”；不能接收时填写真实原因并驳回。
5. 确认后检查收货任务是否生成并具备发布/领取条件。
6. 跟踪有订单收货的良品、破损、拒收记录以及后续上架任务。
7. 对无订单或 Excel 批量入库，按任务号核对库存明细、汇总和流水，不能只看前端成功提示。
8. 核查差异收货行是否有破损、拒收或收货差异原因。普通商品收货是累计数量，上架是本次增量，培训和复核时不能混用。
9. 收货完成不代表入库链路全部结束；确认相关上架任务均已过账，再核对入库单关闭结果。当前 PDA 有订单收货页没有序列号录入控件，序列号任务须安排已验证的入口处理，不能关闭追溯控制强行收货。

## 标准出库确认与任务发布

1. 进入“出库 → 出库单”，筛选当前仓库待确认订单。
2. 确认订单已经提交并由货主管理员审核通过；草稿、待货主审核、已取消或已关闭订单不能确认。
3. 核对货主、仓库、客户、地址、商品、数量、价格审核结果和库存分配。
4. 货主审核通过时系统会冻结库存并生成 `RESERVED` 拣货任务；检查是否只有一个有效任务且已经完整分配。
5. 执行“仓库管理员确认（审核 + 生成拣货任务）”，系统把合法的保留任务发布为 `RELEASED`。
6. 在任务列表确认 PDA 已可见，再安排操作员领取。

系统已经停用“仓库管理员一键确认（货主+仓库审核）”。标准出库必须保留货主管理员审核和仓库管理员确认两个独立控制点。

## 驳回、取消和库存释放

1. 仓库条件不满足时执行仓库管理员驳回，并填写可追踪的处理说明。
2. 系统只允许在相关拣货任务尚未开始、没有执行数量时取消任务并释放冻结库存。
3. 驳回或取消后核对订单状态、任务状态、库存已分配量和可用量。
4. 任务已开始、已完成或已有扫描数量时，先隔离实物并按异常流程处理，不能强行删除任务或订单。
5. 货主业务员撤回和货主管理员取消同样必须经过库存释放校验；发现冻结量未释放立即停止后续出库。

## 任务发布、审核与过账

- 发布前检查任务有有效明细、计划数量大于零、仓库和单据来源一致。
- 已发布未领取任务应明确责任人；执行时间过长时联系现场核对实物状态。
- 任务完成后检查复核状态。标准出库的拣货人与复核人必须分离。
- 管理端审核或过账只用于满足状态条件的任务；未审核通过的任务不得过账。
- 过账失败时保留任务号、错误信息、扫描记录和业务单号，不得通过重建任务绕过原失败。
- 取消任务前确认是否发生实物移动；已经移动的实物先隔离并形成交接记录。

## 库存查询、调整与盘点控制

1. 在库存明细和汇总中按仓库、货主、商品、库位、批次筛选。
2. 使用交易流水、过账分录和快照追溯库存增减来源。
3. 快速入库/出库调整只用于经过批准的差异修正，不用于日常收发货。
4. 调整前保存盘点或差异依据，填写真实原因和关联单号；调整后同时核对明细、汇总和流水。
5. 盘点差异必须复盘确认后处理，禁止为追平报表直接改库存明细。
6. 发现负库存、冻结量异常、过账失败或明细与汇总不一致时停止相关商品作业并升级处理。

## 移库审批、下发与异常处理

1. 确认移库申请/管理及现场执行已启用，管理员和操作员分别使用自己的角色账号。仓库管理员管理任务，不代替操作员领取和扫码。
2. 在仓库 PDA“移库 → 移库管理”查看待审核申请，核对货主、仓库、来源库存或容器、目标库位、数量和原因；不符合条件时点击“驳回”并填写原因。
3. 条件满足后点击“批准”，返回任务列表确认已生成可领取任务。同仓库库存层移库可以更换容器；整容器移库需单独启用且必须更换库位，审批时核对全部容器内实物。
4. 需要由管理岗位直接组织移库时，在“直接下发移库任务”选择仓库、货主、模式、来源、目标、数量和原因，再点击“直接发布”；这属于移库任务，不替代出库单的货主审核。
5. 跟踪操作员分次扫描的累计量和剩余量；整任务过账成功后，核对来源、目标库存及容器位置。审批或扫描成功都不能代替过账核对。
6. 操作员报告异常后，先确认实物位置和已搬数量，处理原因，再在原任务点击“恢复”；需要终止时说明原因执行“整单作废”，并核对预留释放及实物交接。已过账任务不能直接作废。
7. 过账失败时保留原扫描记录，处理库位、库存或系统原因后，在原任务点击“重试过账”。失败未解决前不重建任务、不重复搬运。

## 要货审核与补货监督

1. 由管理员维护补货策略中的仓库、货主、商品、来源库区、目标拣货位、补货单位及阈值。策略管理权限不等于自动补货已启用。
2. 手工要货启用后，在“要货申请”的申请记录查看待审核行，核对目标拣货位、基本单位数量和原因。
3. 来源库存和规则满足时点击“批准”，核对生成的补货任务；不满足时查明原因，不能把审批失败当成已批准或另建重复申请。驳回时填写说明。
4. 阈值和出库需求补货按各自开关及策略运行。核对现有在途补货、可用来源库存和任务来源，避免重复安排人工搬货；后台策略评估产生的任务是否自动发布以策略配置为准。
5. 安排操作员领取并按任务扫描来源库位、商品和目标库位，跟踪剩余量。管理员不代替操作员扫码。
6. 任务完成后核对过账与库位库存。PDA 执行已启用且任务允许重试时，由管理员在原任务执行“重试过账”；其他异常先保存证据交接处理。

## 代办转货和退货出库监督

- 跨货主代办按“原货主 → 新货主 → 客户”核对，原货主库存先预留，拣货与复核完成后统一过账。核对转货单、销售单、任务及原货主转出/新货主转入/销售出库流水，不能把中间转入量当成仓库新增实物收货，也不能重复下发扣库任务。
- 取得查看权限并可登录后台时，可在“代办货权转移单”查看本仓库只读证据；商品对应由系统管理员维护，不在审核中临时改库存归属。
- PDA“退货出库”由有权限的仓库操作员办理，确认即扣库存，不需要仓库管理员审批。规范仓库管理员角色不因此自动获得退货办理或查询入口；由经办人提供记录、统计及退货单号，管理员按本职权限核对库存流水。
- 监督本人草稿、本人确认与整单冲销的责任边界；冲销前核实实物，现场发现破损冲销后仍为破损。不借用经办人账号，不删除流水代替冲销。
- 退货统计按确认/冲销各自日期、各基本单位核对；仓库退供应商不等于已经退款或完成供应商结算，财务另行处理。

## POS 岗位与打印交接

管理仓库不自动取得收银、退货或客户还款权限。兼任 POS 管理时按《POS 使用手册》核对开班、销售、退款、赊账、还款和交班差异；收付款失败或结果不明必须先恢复原记录。销售已完成但打印失败时安排补打，不能要求收银员重新结账。仓库库存监督与 POS 现金实点应分别留下核对结果。

## 报表、导出与额外财务权限

- 默认可查看当前仓库运营报表并按授权导出，核对入库、出库、任务和库存趋势。
- 计费总览、收入和账单不是规范仓库管理员角色的默认权限；只有额外授予仓库财务权限时才可使用。
- 取得财务权限后，按货主、仓库和账期核对费用来源、收费类型和账单行；不得直接改总额掩盖差异。
- 导出文件包含业务范围数据，应按公司数据安全要求保存和传递。

## 常见状态与控制点

| 状态 | 含义 | 操作要求 |
|---|---|---|
| 草稿 / DRAFT | 单据尚未正式提交 | 原创建人可在权限允许时修改、提交或删除未生效内容 |
| 待货主审核 / OWNER_PENDING | 业务员已经提交 | 等待货主管理员通过、退回或取消 |
| 货主已通过 / OWNER_APPROVED | 商业条件已确认，库存可能已冻结 | 等待仓库管理员确认并发布任务 |
| 待仓库确认 / WHS_PENDING | 等待仓库接单 | 仓库管理员检查仓库、库存和履约条件 |
| 仓库已确认 / WHS_APPROVED | 已进入仓库履约 | 不得随意修改原订单 |
| 保留 / RESERVED | 任务已因货主审核创建但尚未发布 | 仓库确认前不得现场执行 |
| 待发布 / READY | 任务具备发布条件 | 由仓库管理员发布 |
| 已发布 / RELEASED | 操作员可以领取或执行 | 按任务逐行扫描作业 |
| 执行中 / IN_PROGRESS | 已发生现场作业记录 | 继续完成剩余任务行，不得另建重复任务 |
| 已完成 / COMPLETED | 作业数量已经完成 | 等待复核、审核或过账 |
| 待审核 / PENDING | 需要复核或管理确认 | 核对实物、数量、批次和库位 |
| 已过账 / POSTED | 库存影响已正式生效 | 错误只能通过规范冲销或批准的调整处理 |
| 过账失败 / FAILED | 库存写入没有成功完成 | 保留原任务号和错误信息，交管理员处理 |
| 已驳回 / REJECTED | 审核未通过 | 查看原因并按流程修改、重提或终止 |
| 已取消 / CANCELLED | 单据或任务终止 | 核对冻结库存是否释放、现场实物是否隔离 |
| 异常 / EXCEPTION | 移库任务处于异常执行状态 | 操作员说明现场情况，管理员处理原因后决定恢复或作废 |
| 退货已冲销 / REVERSED | PDA 退货整单已恢复原库存维度 | 原退货记录保留；现场发现破损仍恢复为破损，不再重复补库存 |

关键控制点：

- 货主管理员审核是商业确认，仓库管理员确认是履约确认，两者不能互相替代。
- 标准出库必须先完成货主审核，再由仓库管理员确认发布；系统已停用仓库端代替货主审批的一键流程。
- 拣货完成不等于库存已经扣减；以任务过账状态 `POSTED` 和库存流水为准。
- 取消、撤回或驳回涉及已冻结库存时，必须核对分配量已经释放；任务已开始或已有执行数量时，系统会阻止直接取消。
- 移库和补货需要同时看任务状态、行完成量和过账状态；分次扫描只累计执行数量，库存移动以整任务过账成功为准。
- 移库异常执行状态与过账失败不是同一件事；“恢复”用于异常任务，“重试过账”用于过账失败，均由有权限的仓库管理员处理。
- POS 销售状态和班次状态按《POS 使用手册》核对；现场还款或打印完成情况不能由普通仓库任务状态推断。
- 同名状态必须结合单据类型解释：PDA 退货 `COMPLETED` 已直接扣库；代办货权转移 `RESERVED` 是待转货，`POSTED` 是已转货并销售出库。不能套用普通任务的“已完成、待过账”结论。

## 异常处理与问题上报

### 无法登录或菜单缺失

按“网络 → 正式入口 → 用户名和密码 → 账号启用状态 → 职员状态（仅 Web 后台）→ 角色范围 → 规范角色组 → 功能开关及额外权限”的顺序检查。移库、补货等功能即使有角色权限，也可能尚未启用。登录过于频繁时按页面提示等待，由系统管理员检查账号和审计日志。

### 数据为空或范围不正确

先清除筛选并刷新，再核对当前角色和货主/仓库范围。看到不属于本范围的数据时立即停止操作并上报，不得导出或转发。

### 网络超时或重复提交提示

不要连续点击。先回到列表按单号、任务号或平台单号查询；带幂等保护的操作可以使用同一请求重试，但不能改动内容后继续使用原请求标识。

- 移库、补货扫描结果未确认时，保留当前页的原库位、商品、容器、序列号和数量再试；提示“已确认此前扫描记录”表示恢复了原结果，不能再次搬货。离开页面后先查原任务再决定下一步。
- 收货与上架使用不同数量口径：普通商品有订单收货登记当前行累计数量，上架登记本次增量。重试前不要把累计数量当作新增数量再次录入。
- POS 还款结果未确认时，回到原收银员、原仓库和原客户核对并恢复该笔还款；不能更换客户或金额当作新收款。具体步骤见《POS 使用手册》。
- PDA 退货出库出现“继续确认结果”时，使用原账号、原仓库恢复原请求；冲销待确认也不能另建退货单抵消。跨货主代办同时按销售单号、转货单号和任务号查原结果。
- Android 拣货、收银或 POS 退货出现待确认提示时，保留原设备本地数据，使用页面提供的原请求恢复按钮。不要清应用数据、修改原请求或换账号继续办理，具体区别见《Android 移动端使用手册》和《POS 使用手册》。

### 打印失败或打印页过期

1. 先核对原单是否已成功保存或结账，保留单号。
2. 从原收货任务、出库记录、POS 销售单或班次记录重新点击打印；打印页过期时不要反复使用原链接。
3. 浏览器阻止新窗口时，按设备提示允许本系统打开打印窗口，再从原记录重试。
4. “打印已发起”不代表纸张已输出；核对打印机、纸张和实际份数。结账成功但打印失败时仅补打，不能重新结账。

### 移库、补货过账失败

扫描数量已保存不代表库存已移动。保留原任务号、来源和目标库位、已搬数量及完整错误信息，交仓库管理员处理原任务；管理员修复原因后按权限重试过账，不能新建任务重复搬货或修改库存数。

### 库存、任务或账单不一致

保留页面截图和原始单号，按“业务单据 → 任务 → 扫描记录 → 过账状态 → 库存流水/计费来源”逐层核对。禁止通过删除记录或直接改汇总数掩盖差异。
