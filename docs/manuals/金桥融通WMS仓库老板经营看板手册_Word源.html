本手册仅描述当前代码中具有有效权限、页面和业务闭环的功能。

文档版本： V2.2

适用系统版本： 2026-10-17 当前工作区业务基线

适用对象： 仓库老板

正式权限组： WMS::仓库老板

主要入口： 仓储经营分析中心（wmsbossbilling）

文档状态： 交付版

本手册按当前业务代码、权限校验、客户端页面和自动化测试契约编写。实际菜单由角色、权限和显式数据范围共同决定。

使用范围

项目 本角色要求
角色 仓库老板
正式权限组 WMS::仓库老板
主要入口 仓储经营分析中心（wmsbossbilling）
数据范围 一个或多个明确授权的仓库范围

本册可独立用于培训和日常操作，不要求先阅读合订版。涉及其他岗位时，只说明交接点，不授权本角色代替其他岗位操作。

登录、账号与通用安全

首次登录

  1. 从系统管理员处取得正式入口、用户名和初始密码。
  2. 打开本岗位对应的应用或 Web 地址，输入用户名和密码。
  3. 登录后核对显示姓名、业务角色以及货主或仓库范围。
  4. 首次登录立即进入“我的 → 修改密码”或 Web 右上角密码修改入口。
  5. 如果能够登录但没有菜单，不要借用其他账号，记录用户名、入口和页面截图并联系系统管理员。

登录失效与切换账号

  1. 使用管理员提供的正式入口；客户端的服务地址由部署配置决定，不在登录页自行改接其他服务器。
  2. 使用过程中客户端会尝试续期登录。临时断网或服务器繁忙时先检查网络，恢复后重新查询当前单据；不能把网络故障当成业务未提交。
  3. 明确提示登录失效并返回登录页时，重新登录本人账号，再核对角色、仓库或货主范围。
  4. 看到“登录账号已变化”或“登录状态已变化”时停止当前操作，刷新页面并重新选择业务对象。旧账号的页面结果不能作为新账号继续操作的依据。
  5. 连续登录过频时按提示等待，不连续点击；仍不能登录则联系管理员检查账号。

账号和数据范围

  • 一人一号，不得共用账号或把密码留在 PDA、电脑旁。
  • 角色决定能够执行什么操作；显式角色范围决定能够操作哪个货主或仓库的数据。
  • 普通 WMS 用户只能启用一种业务角色。除仓库老板可授权多个仓库外，其他角色只能有一个活动范围。
  • 超级管理员使用全局权限，不设置业务角色范围；超级管理员账号不得用于日常开单、审批和现场作业。
  • 离职、调岗、合作终止或设备丢失后，应立即停用账号并保留审计记录。

通用操作原则

  1. 操作前核对货主、仓库、客户、商品、批次、库位和单据号。
  2. 扫码后必须核对系统命中的商品名称和规格，不能只凭提示音继续。
  3. 审核、复核、过账、取消和库存调整会改变业务状态或库存，提交前必须再次确认。
  4. 系统提示成功后再离开页面；网络中断时先查询原单状态，确认未成功后才重试。
  5. 禁止通过直接修改库存明细来代替正常收货、上架、拣货、复核、盘点或调整流程。
  6. 页面入口可见不代表账号一定有执行权限；最终以服务器返回的角色、权限和数据范围校验为准。

修改密码与退出

  1. 修改密码时输入原密码、新密码和确认密码；新密码必须通过系统安全校验。
  2. 修改成功后退出，并用新密码重新登录验证。
  3. 当班结束或共用设备交接前必须从“我的”或用户菜单执行退出，不能只关闭屏幕或浏览器。
  4. 切换账号前先记录尚未确认的单号、任务号及收付款结果；下一位人员使用自己的账号重新打开业务页面，不接着提交上一账号遗留的内容。

角色职责与只读边界

仓库老板通过“仓储经营分析中心”查看一个或多个授权仓库的经营、库存、计费和预警。规范角色组为 WMS::仓库老板；这是唯一允许同一账号配置多个活动仓库范围的业务角色。

仓库老板默认角色模板拥有老板看板、仓库运营、仓库财务、报表导出和例会快照创建权限。经营分析中心用于查看经营数据及按权限保存分析快照，不用于开单、审批、库存调整、任务发布或过账。

旧用户组“仓库主管”会作为仓库老板兼容别名识别。需要执行仓库确认和任务管理的作业主管应使用 WMS::仓库管理员，不能使用本角色。

登录与范围确认

  1. 登录“仓储经营分析中心”，核对显示姓名、仓库名称和货主范围。
  2. 多仓账号只能看到已配置的仓库；切换范围后确认页面数据截至时间。
  3. 使用“全部货主”查看仓库整体，或选择具体货主进行对比。
  4. 数据为空时先核对仓库与日期范围，不要要求系统管理员临时扩大权限。

筛选、刷新与失败恢复

“全部仓库”仅包含当前账号已授权仓库。仓库、货主和日期选择会在经营页面间沿用，打开下钻页或返回总览后先看筛选栏，不能把上一次单仓结果当作全部仓库结果。

日期使用有效的起止日，开始日不能晚于结束日，结束日不能晚于系统当天；最大范围为含首尾的 367 天。默认通常为当月开始至当天，以页面实际筛选栏为准。改范围后等待新结果；加载或查询失败时按提示重试，旧结果不作为当前范围的最新数据。

库位、预警或收费记录翻页失败时重试原页，不跳过失败页。导出被拒绝时记录服务器原因并检查范围、权限和日期，不把下载失败当成空报表。

首页总览

  1. 查看“今日实际收发量”、库存 SKU、库位占用率、体积利用率、“所选区间应计”、逾期应收和预警数。今日实绩与所选区间费用使用不同时间口径，不能混作同一天指标。
  2. 在“今日作业节奏”比较今日新任务完成量、完成率和当前积压。
  3. 查看收入贡献排行、占仓 Top 货主和近 7 天趋势。库存数量按单位分组，金额按原币分组；不同单位或币种不能直接相加。
  4. 对完成率下降、积压增加、占仓高但收入低或预警集中项进入对应页面追踪。
  5. 页面上的“实绩截至”用于判断数据新鲜度；数据未更新时先确认报表刷新状态。
  6. 草稿账单不计入已出账，收入贡献排行当前不含成本，不能把应计收入称为已收现金或利润。页面提示旧数据、缺失或估算时保留该说明后再用于会议。

库存与库容

  1. 切换仓库和货主范围，查看在库、可用、7 天临期、30 天未变化、库位占用率和体积利用率。
  2. 查看货主占仓排行和高占用热区，识别仓容紧张区域。
  3. 查看低效冷区、临期库存和呆滞库存明细。
  4. 点击库存明细追溯商品、货主和库位；看板数值用于经营判断，库存处置必须交仓库按业务流程执行。
  5. 呆滞口径以系统当前展示说明为准，不把代理指标直接当作财务减值结论。

收入与计费

  1. 按仓库、货主、收费类型、日期和应计状态筛选。
  2. 查看货主数、应计条数、不含税小计、税额、价税合计和已出账金额。
  3. 通过货主排名、收费结构、状态分布和每日趋势判断收入质量。
  4. 点击货主、最近收费记录或账单进入明细，追溯服务日期、费用类型、数量、单价和金额；金额比较须使用相同币种和时间范围。
  5. 在账单详情按日期、费用类型和关键词筛选，分别核对整单金额与当前筛选小计。点击可下钻的账单行查看对应收费记录；这与货主端只展示费用行的入口不同。
  6. 发现金额异常时记录范围、账期、收费类型和来源单号，交货主管理员与财务核对，不在老板端修改。POS 客户欠款与仓储服务账单是不同业务，不能用此看板代办客户还款或交班。

从货主明细进入账单，再进入收费记录时，保留仓库、货主和日期上下文；返回后核对筛选与分页。费用更新后重新查询整条下钻链路，不能混用刷新前后的总额与明细。按面积月费分摊的日应计，以服务日期所在月份天数计算，不用统一 30 天手工估算。

预警中心

预警中心集中展示当前代码提供的经营关注项，例如超期任务、逾期账单、计费任务失败、待复核任务、临期库存和复核差异。

  1. 先按风险级别和数量判断优先级。
  2. 打开预警项核对仓库、货主、单号、发生时间和当前状态。
  3. 将任务类问题交仓库管理员，订单/账单类问题交货主管理员或财务，系统故障交系统管理员。
  4. 后续回到预警中心确认数量下降或状态关闭，不能只依赖口头反馈。

经营驾驶舱

从导航进入“经营驾驶舱”，先核对沿用的仓库、货主和日期，再切换标签。每次切换后等待当前标签加载成功，关注数据截至时间、近似来源或不可用提示。

标签 阅读与交接重点
收入保障 未定价、漏应计、晚到费用、近似来源、计费失败、待关账及关账阻断；交财务或系统管理员追溯
应收回款 按原币看未收余额及滚动 90 天 DSO（回款周期指标）；“不可用”不能当成零天，余额不等于本期收入
运营履约 实际入出库单/行、订单级准时率、齐套率、OTIF（按时足量交付）、SLA 覆盖率、履约周期和任务积压；数量按基本单位明细查看
资源收益 按币种比较货主收入及资源贡献差值，不直接作为利润
目标预测 所选区间与前一期比较、月底预测算法和样本天数；预测不等于实际或承诺收入
库存风险 FIFO 成本层价值与库龄分层；缺少成本层或来源不完整时先确认数据质量，不作正式估值
预警闭环 查看案件级别、状态、责任人和期限；按页查看，处置由授权管理员或财务完成

有导出权限时，运营履约使用“导出运营明细”，其他支持标签使用“导出当前报表”；预警闭环不提供该报表按钮。页面失败时先重试，不导出或引用旧结果。

“创建例会快照”按 can_create_business_review_snapshot 能力显示；当前老板默认模板包含创建权限，既有定制组仍需核对实际授权。仅有看板查看权限不等于可以创建快照。核对范围和当前数据后保存快照供会议追溯；它不是业务审批，也不会代办预警处置、收款或库存变更。

经营例会建议

  • 每日：作业完成率、积压、超期任务、待复核、临期库存和计费失败。
  • 每周：近 7 天入出库趋势、仓容、高低效区域、货主占仓排行和收入排行。
  • 每月：收费结构、账单状态、逾期应收、资源占用与收入匹配度。
  • 导出报表用于正式会议时记录导出范围、时间和数据截至点，防止不同口径混用。

老板日常检查表

  • 当前查看的是正确仓库、货主和日期范围。
  • 已关注作业积压、待复核和超期任务。
  • 已关注临期、呆滞库存和仓容热点。
  • 收入、计费、账单和逾期应收趋势可解释。
  • 已区分原币金额、计量单位、整单/筛选小计、草稿/已出账及应计/实收口径。
  • 高风险预警已有责任人和处理时限。
  • 经营端未执行或要求他人绕过业务流程修改数据。

常见状态与控制点

状态 含义 操作要求
草稿 / DRAFT 单据尚未正式提交 原创建人可在权限允许时修改、提交或删除未生效内容
待货主审核 / OWNER_PENDING 业务员已经提交 等待货主管理员通过、退回或取消
货主已通过 / OWNER_APPROVED 商业条件已确认，库存可能已冻结 等待仓库管理员确认并发布任务
待仓库确认 / WHS_PENDING 等待仓库接单 仓库管理员检查仓库、库存和履约条件
仓库已确认 / WHS_APPROVED 已进入仓库履约 不得随意修改原订单
保留 / RESERVED 任务已因货主审核创建但尚未发布 仓库确认前不得现场执行
待发布 / READY 任务具备发布条件 由仓库管理员发布
已发布 / RELEASED 操作员可以领取或执行 按任务逐行扫描作业
执行中 / IN_PROGRESS 已发生现场作业记录 继续完成剩余任务行，不得另建重复任务
已完成 / COMPLETED 作业数量已经完成 等待复核、审核或过账
待审核 / PENDING 需要复核或管理确认 核对实物、数量、批次和库位
已过账 / POSTED 库存影响已正式生效 错误只能通过规范冲销或批准的调整处理
过账失败 / FAILED 库存写入没有成功完成 保留原任务号和错误信息，交管理员处理
已驳回 / REJECTED 审核未通过 查看原因并按流程修改、重提或终止
已取消 / CANCELLED 单据或任务终止 核对冻结库存是否释放、现场实物是否隔离
异常 / EXCEPTION 移库任务处于异常执行状态 操作员说明现场情况，管理员处理原因后决定恢复或作废
退货已冲销 / REVERSED PDA 退货整单已恢复原库存维度 原退货记录保留；现场发现破损仍恢复为破损，不再重复补库存

关键控制点：

  • 货主管理员审核是商业确认，仓库管理员确认是履约确认，两者不能互相替代。
  • 标准出库必须先完成货主审核，再由仓库管理员确认发布；系统已停用仓库端代替货主审批的一键流程。
  • 拣货完成不等于库存已经扣减；以任务过账状态 POSTED 和库存流水为准。
  • 取消、撤回或驳回涉及已冻结库存时，必须核对分配量已经释放；任务已开始或已有执行数量时，系统会阻止直接取消。
  • 移库和补货需要同时看任务状态、行完成量和过账状态；分次扫描只累计执行数量，库存移动以整任务过账成功为准。
  • 移库异常执行状态与过账失败不是同一件事；“恢复”用于异常任务，“重试过账”用于过账失败，均由有权限的仓库管理员处理。
  • POS 销售状态和班次状态按《POS 使用手册》核对；现场还款或打印完成情况不能由普通仓库任务状态推断。
  • 同名状态必须结合单据类型解释：PDA 退货 COMPLETED 已直接扣库；代办货权转移 RESERVED 是待转货，POSTED 是已转货并销售出库。不能套用普通任务的“已完成、待过账”结论。

异常处理与问题上报

无法登录或菜单缺失

按“网络 → 正式入口 → 用户名和密码 → 账号启用状态 → 职员状态（仅 Web 后台）→ 角色范围 → 规范角色组 → 功能开关及额外权限”的顺序检查。移库、补货等功能即使有角色权限，也可能尚未启用。登录过于频繁时按页面提示等待，由系统管理员检查账号和审计日志。

数据为空或范围不正确

先清除筛选并刷新，再核对当前角色和货主/仓库范围。看到不属于本范围的数据时立即停止操作并上报，不得导出或转发。

网络超时或重复提交提示

不要连续点击。先回到列表按单号、任务号或平台单号查询；带幂等保护的操作可以使用同一请求重试，但不能改动内容后继续使用原请求标识。

  • 移库、补货扫描结果未确认时，保留当前页的原库位、商品、容器、序列号和数量再试；提示“已确认此前扫描记录”表示恢复了原结果，不能再次搬货。离开页面后先查原任务再决定下一步。
  • 收货与上架使用不同数量口径：普通商品有订单收货登记当前行累计数量，上架登记本次增量。重试前不要把累计数量当作新增数量再次录入。
  • POS 还款结果未确认时，回到原收银员、原仓库和原客户核对并恢复该笔还款；不能更换客户或金额当作新收款。具体步骤见《POS 使用手册》。
  • PDA 退货出库出现“继续确认结果”时，使用原账号、原仓库恢复原请求；冲销待确认也不能另建退货单抵消。跨货主代办同时按销售单号、转货单号和任务号查原结果。
  • Android 拣货、收银或 POS 退货出现待确认提示时，保留原设备本地数据，使用页面提供的原请求恢复按钮。不要清应用数据、修改原请求或换账号继续办理，具体区别见《Android 移动端使用手册》和《POS 使用手册》。

打印失败或打印页过期

  1. 先核对原单是否已成功保存或结账，保留单号。
  2. 从原收货任务、出库记录、POS 销售单或班次记录重新点击打印；打印页过期时不要反复使用原链接。
  3. 浏览器阻止新窗口时，按设备提示允许本系统打开打印窗口，再从原记录重试。
  4. “打印已发起”不代表纸张已输出；核对打印机、纸张和实际份数。结账成功但打印失败时仅补打，不能重新结账。

移库、补货过账失败

扫描数量已保存不代表库存已移动。保留原任务号、来源和目标库位、已搬数量及完整错误信息，交仓库管理员处理原任务；管理员修复原因后按权限重试过账，不能新建任务重复搬货或修改库存数。

库存、任务或账单不一致

保留页面截图和原始单号，按“业务单据 → 任务 → 扫描记录 → 过账状态 → 库存流水/计费来源”逐层核对。禁止通过删除记录或直接改汇总数掩盖差异。
