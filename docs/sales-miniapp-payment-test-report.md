# 商城微信支付结算测试报告

测试日期：2026-08-27

## 1. 测试范围

本轮在隔离 MySQL 数据库 `wms_db_test` 上验证商城订单金额、微信预支付、主动查单、
支付和退款回调、订单超时、库存冻结与释放、优惠权益、并发和前端支付确认逻辑。
正式数据库 `wms_db` 只执行数据准确性只读检查，没有创建、修改或删除业务数据。

真实微信商户参数尚未配置，因此本报告只确认第一阶段自动化测试，不确认真机交易。

## 2. 本轮修复

- 修复订单确认页把 `0.00` 当成假值并回退到商品原金额的问题。
- 将前端支付流程提取为可注入服务，客户端返回成功后仍按 1、2、3、5 秒主动查单；
  只有后端确认 `PAID` 才返回支付成功。
- 用户取消支付后仍查单一次；查单不确定时显示支付结果确认中。
- 零元订单走 `INTERNAL_ZERO`，不调用 `uni.requestPayment`。
- 修复 AES-256-GCM 密文被篡改时 `InvalidTag` 泄漏为未处理异常的问题，统一返回
  微信回调资源解密失败。
- 发布门禁默认重建 `wms_db_test` 并回放完整迁移，拒绝正式库名、`--fast-db` 和
  `--no-migrations`。

## 4. 已覆盖的支付风险

- 后端权威金额、零元、分值舍入、负数拒绝和前端金额篡改隔离。
- 未付款订单禁止仓库确认、任务领取、拣货和库存过账。
- 支付成功、未付款取消、超时关单、延迟到账自动退款和库存守恒。
- `SUCCESS`、`USERPAYING`、`NOTPAY`、`CLOSED`、`REVOKED`、`PAYERROR`、
  未知状态、网络异常及关单时已支付竞态。
- 重复预支付、固定商户单号恢复、支付成功与取消并发。
- 支付和退款回调各重放 20 次，事件、金额、权益和库存不重复处理。
- 退款 `PROCESSING` 查询恢复，以及 1、5、15、60、180、360 分钟退避后转人工。
- RSA 响应验签、序列号选公钥、未知序列号拒绝、时间戳和报文篡改。
- 使用真实 AES-256-GCM 构造和解密回调资源，篡改密文必须拒绝。
- AppID、商户号、币种、金额、商户订单号和退款单号不匹配必须拒绝。
- 单条超时或退款异常不影响同批次后续记录处理。
