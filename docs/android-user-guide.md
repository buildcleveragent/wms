# Android 移动端使用手册

- 文档版本：V2.2
- 业务基线：2026-10-17 当前工作区，包含未提交修改；不表示已部署。
- 适用入口：`wmsandroid` Android 移动端；岗位权限仍由服务端决定。
- 相关文档：[岗位手册索引](manuals/README.md) · [POS 使用手册](pos_user_manual.md) · [扫描头验收说明](../wmsandroid/docs/android-scanner-acceptance.md)。

本手册补充 Android 页面与原 PDA 的差异。本次按源码核对，未安装或发布 APK，未做真机、扫描头或打印机验收。

## 1. 登录与设备交接

使用管理员交付的应用和正式服务入口，输入本人账号、密码。登录后核对身份、仓库和可用菜单。登录失效后回原账号确认未完成业务；账号切换后重新打开业务页面，不能沿用前一个账号的查询结果。

交接前记录待确认销售、退货或拣货操作，保留原设备本地数据。临时断网先恢复网络，不清应用数据、不卸载重装来解决待确认业务。

## 2. 收货、上架、移库与补货

按对应仓库角色手册核对任务、库位、批次、效期和数量口径：有订单普通商品收货登记累计量，上架、移库、补货登记本次增量。移库与补货须先启用相应功能，扫描保存不等于整任务已经过账。

只使用本安装版本实际开放的页面。原 PDA 的代办转货、退货出库和商品 Excel 页面不能据此推断 Android 具备同样入口；需要使用这些流程时按管理员提供的已验证入口操作。序列号等追溯控制必须按当前表单支持情况确认，不关闭商品控制绕过限制。

## 3. 拣货与扫描结果恢复

1. 打开本人可操作任务，核对仓库、货主、计划量、完成量和过账状态，按页面先领取、开始。
2. 到任务指定位置核对实物，扫描商品或输入条码，填写本次扫描数量。箱码按命中包装快照换算基本数量；看累计完成量后再扫下一次。
3. 出现“拣货结果待确认”时，点击“继续确认结果”。系统保留原条码、数量和请求编号；确认前不要修改行数量或继续扫同一批实物。
4. 返回或重新打开页面后仍有待确认操作时，先恢复原请求。提示本地恢复记录异常则记录任务号并交管理员核对，不自行删除记录。
5. 全部拣货完成后按页面完成并交复核；库存以最终过账状态和流水为准。标准出库的拣货人与复核人须分离。

## 4. Android POS 的库存与选品

Android 收银使用绑定仓库的**全仓可用库存**；原 `wmspda` 收银使用**拣货区库存**。同一商品在两端显示可售量不同，先核对库存范围，不直接判为库存错误。

1. 先开本人班次，在 POS 查询或扫码商品，核对货主、规格、基本单位及包装。
2. 同条码匹配多个货主时，等待候选查询完成后明确选择。缺货候选会保留显示，但不能加入购物车；不能自动用另一货主替代。
3. 包装无法确认时停止扫码加入，交管理员核对标识；必要时按页面手工选择商品和单位，不能把未知包装当成一件。
4. 同一货主同一商品的不同包装按基本数量合并校验库存；拆成多行不会扩大可售量。
5. 核对客户、数量、价格和总额后进入收款；收银权限和仓库授权必须同时满足。

## 5. 记录收款与恢复销售

顾客实际完成付款后，再选择现金、微信、支付宝或银行卡，填写实收及可选流水号，核对找零，点击“确认已收款并记录销售”。这些选项记录现场付款方式，不会联机向支付通道扣款。

出现“上一笔销售结果待确认”时，保持原账号、仓库、商品、客户和付款内容，点击“重试确认”。待确认期间购物车锁定；刷新或重开页面后先恢复原请求，不能再收一次钱或另开销售替代。成功后按销售单号、明细、付款及库存核对，打印问题从原销售补打。

赊账、客户还款、拆分支付、对账及主管重开等完整业务规则见 POS 专项手册；使用本版本已提供的入口，需要其他能力时由管理员安排相应客户端，不在移动页面自行拼接替代交易。

## 6. 销售退货与退款记录

1. 在销售历史打开原销售，核对销售单号、仓库、收银员、货主及可退数量。
2. 有退货和退款权限、本人当前班次可用时，点击“退货”，按基本数量填写各行本次退货量及原因。
3. 选择实际退款方式，核对本次退款金额，确认实物退回及资金处理后点击“确认退货并记录退款”。赊账退款表示冲减欠款，不是现金支付。
4. 出现“退货结果待确认”时点击“继续确认结果”，沿用原请求；不要重新退货或再付一笔退款。成功后核对剩余可退数量、原库存回补和班次汇总。
5. 部分或全部退货保留原销售记录；整单作废是另一流程，须满足原销售、班次及还款等限制，不能拿作废绕过退货规则。

Android POS 退货的请求恢复与 `wmspda` 当前退货页不同；不要把 Android 的持久恢复能力推断到所有客户端。

## 7. 班末与故障上报

先处理结果不明操作，再核对班次销售、退款、现金实点及交班差额。只交本人班次，退出后由接班人登录开班。

上报时保留时间、应用版本、账号角色、仓库、任务或销售单号、原错误及是否已移动实物/收退款。硬件扫码、弱网恢复、文件打开及物理出纸须按现场设备单独验收；浏览器测试结果不能代替 Android 真机结果。
